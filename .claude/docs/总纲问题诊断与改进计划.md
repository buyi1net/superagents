# dz-skills 总纲:问题诊断与改进计划

更新到 2026-06-20(今天讨论后)。供你考虑"规则怎么管理、规划"用。

今天的重点不在改了哪句话,在把"dz-skills 该怎么管"想清楚了。所以先看架构共识,再看具体问题状态。

---

## 一、架构共识(今天最大的收获)

1. **一句话定位**:dz-skills 是你唯一要自己维护的"行为纪律总纲"。技能(方法)全从网上拿,不自己养。

2. **三样东西要分清,放的地方不同**:
   - 纪律(行为对不对:别删原件、动手前确认):通用,归 dz-skills 核心,常驻。
   - 规格(做出来啥样:logo 放哪、什么色、多大):某技能专属,归 dz-skills 的场景 module。放网上 skill 里会被更新冲掉,所以收进你自己维护的总纲。
   - 技能方法(怎么处理 PDF/Excel/视频):外部、易变、会过时,网上拿、用完即弃,不维护。

3. **切分:主文件 vs module**。每次都可能用到的(核心纪律)留主文件常驻;只进特定场景才用的(某场景纪律 + 规格)拆场景 module、路由进来。判据:脱开这个场景还成不成立,成立留主文件,不成立拆 module。

4. **用 module,不做独立 skill**。纪律细则挂 dz-skills 下当 module。module 靠主文件路由触发(确定),独立 skill 靠 description 召回(概率、会漏),且 module 归属一致、跟核心红线联动。

5. **可靠性靠 hook,不靠模型自觉**。模型会不会去读场景规则,靠自觉就是概率,弱模型、长上下文会漏。要"进场景必读"只有 hook 能保证。所以:内容归 module,可靠性归 hook,两件分开。

6. **dz-skills 是所有 skill 的地基**。任何技能干活都在读写文件、跑命令,都受 dz-skills 核心纪律管。能力 skill 管"做什么",dz-skills 管"动电脑的底线"。

7. **创作豁免**。创作场景(诗、小说、文案)去 AI 痕迹那套让路(放开修辞、华丽、造词、铺陈);但车轱辘、空话任何时候不豁免。规则管行为不管能力——文采看模型,不归规则操心。

### 新发现(2026-06-24,待办)

- **收尾红线不被遵守**:其它 agent 基本不遵守。诊断——名字"收尾"不直观是次因;主因是表述太抽象绕弯(判据要绕几个弯、三种形态是分类学)、缺正例(通篇负面定义,正面只"说透就停"一句)、对抗 RLHF 礼貌本能力度不够(没点名高频违规话 + 给替代)。老大要自己重写。方向:名字直白("别把球踢回用户"类)、多给"这句 → 换这句"对照、点名高频违规话("要不要我…""你看行吗")、配收尾自检钩子。
