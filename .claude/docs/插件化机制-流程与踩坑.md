# superagents 插件化机制与踩坑

> 记录日期:2026-07-05。基于本机 Windows 实测,外加此前三家跨平台安装验证。
> 用途:把插件化的机制、安装流程、已知坑的排查方法落在一处。出问题时对照排查;新会话或新 agent 接手时先读这份。
> 标注约定:**实测** = 本机验证过、有证据;**推测** = 有旁证但没直接验证,别当结论用。

---

## 最要紧的几条(先看这个)

1. **codex 认 github,不认本地改动。** codex 会话启动时若检测到 github 有更新,就从 github 完整重新 clone 一份到本地 cache。用 `sync.mjs` 刷进 codex cache 的本地改动,它下次一对齐就覆盖回 github 版。所以**开发时想让 codex 读到新正稿,必须 commit + push,光 sync 没用**。(实测)

2. **CC 和 opencode 用 `sync.mjs` 刷本地 cache 就够**,不必 commit。它们不像 codex 那样启动时重拉 github 覆盖本地改动,sync 刷进去持久生效。(Windows 已验证;macOS 待验,见「六」)

3. **codex cache 是全量仓库 5.9M,真正加载的只有 61K**(`.codex-plugin` + `skills`),其余是 `.git`(2.2M)、`.claude`、别家清单等杂物。codex 重 clone 后不做任何清理,`install.mjs` 的白名单清理对它无效。(实测)

## 一、插件化架构

一个仓库同时供三家 agent 使用。命名与版本:

- market(市场):`superagents-dz`
- plugin(插件):`superagents`
- version:`0.2.0`
- 核心 skill:`constitution`(规则总纲,正稿在 `skills/constitution/`)

三家的注入方式和强度:

| Agent | 注入方式 | 强度 | 本地 cache 路径 |
|---|---|---|---|
| Claude Code | SessionStart hook 注入全文 | 强(开场强制) | `~/.claude/plugins/cache/superagents-dz/superagents/<版本>/` |
| OpenCode | 插件 transform 注入全文 | 强(开场注入首条消息) | `~/.cache/opencode/packages/superagents@.../node_modules/superagents/` |
| Codex | skill 引用(开场露 description,正文按需调) | 软(靠模型自觉) | `~/.codex/plugins/cache/superagents-dz/superagents/<版本>/` |

Codex 走 skill 引用而非 hook,是因为它的 hook 对 `exec` 不触发(见坑 5),交互场景只能靠模型自己调 skill。

各家的清单目录(`.claude-plugin`、`.codex-plugin`、`.opencode`、`.agents/plugins`)必须放在仓库根:安装时各家先扫根目录认出自己的 plugin,再按清单去 `hooks/`、`skills/` 取内容。

## 二、三家安装机制

由 `scripts/install.mjs` 统一处理。三家的拉取方式不同,cache 干净程度也不同。

**Claude Code:**
- `claude plugin marketplace add <完整 HTTPS URL> --sparse .claude-plugin hooks skills`,只拉这三个目录。
- 装完按白名单 `CC_KEEP`(`.claude-plugin`/`hooks`/`skills`/`.in_use`)清 cache,再 `pruneOldVersions` 删旧版本目录。
- 必须用完整 HTTPS URL,不能用 `buyi1net/superagents` 短格式(见坑 3)。

**Codex:**
- `codex plugin marketplace add` + `codex plugin add`,整仓拉(不能 sparse,partial clone 缺 blob 会失败)。
- 装完按白名单 `CODEX_KEEP`(`.codex-plugin`/`skills`)清 cache。**但这步对 codex 基本无效**,见坑 2。

**OpenCode:**
- 只往 `~/.config/opencode/opencode.json` 的 `plugin` 数组写一行 git 依赖地址,首次运行才真正拉包,且拉整仓、带杂物。
- 装完补跑 `scripts/clean-opencode.mjs` 清缓存杂物(3.8M → 66K,见坑 7)。

## 三、codex 缓存机制(本会话重点)

codex 这套机制是本会话挖得最深的部分,单独展开。

### 两层缓存

```
github  ──(git clone,走网络)──▶  第一层:marketplace 缓存        ──(git clone,纯本地)──▶  第二层:plugin cache
                                 ~/.codex/.tmp/marketplaces/                              ~/.codex/plugins/cache/.../<版本>/
                                 superagents-dz/                                          (实际被加载的这份)
```

- 第一层 marketplace 缓存:从 github 完整 clone。`.git/logs/HEAD` 只有一条 `clone: from https://github.com/...`,`shallow: no`(完整克隆),没有 fetch/pull 记录。
- 第二层 plugin cache:从**本地**第一层 clone(reflog 显示 `clone: from ...\.codex\.tmp\marketplaces\...`),不碰网络。

要点:真正联网下载只发生在第一层。第二层是本地 clone,即使重建也不走网络。

### 触发逻辑:有更新才重 clone,一致就不动

- **有更新触发**:2026-07-05 05:01 推送新 commit `aa7ce7e` 后,开 codex TUI,第一层从 github 重新 clone、第二层随之重建,cache 更新到 `aa7ce7e`。
- **一致不触发**:05:41 在缓存已等于 github 的状态下新开一次 TUI 会话(history 记录证明会话确实发生),第一层 clone 时间戳、第二层 mtime、reflog、staging 目录**全部停在 05:01、没有任何变化**。(实测)
- **exec 完全不触发这套同步**:跑一次 `codex exec`,两层缓存和 staging 零变化。exec 是精简 headless 模式,不做 plugin 同步(也不触发 SessionStart hook,见坑 5)。(实测)

结论:codex 不是每次会话都重下,而是检测到 github 有更新才重 clone。正常使用(装了用 github 版)稳定持久,只在推了新版后第一次开会话时同步一次。

### 重 clone 是完整 clone,且不清理

- 更新方式是**整个删掉、从 github 完整重 clone**,不是增量 pull(第一层 `logs/HEAD` 只有 clone、无 fetch/pull;`shallow: no`)。触发时是全量拉整个仓库。
- 重 clone 后**不做任何清理**:0.2.0 全量 5.9M,codex 真正加载的只有 61K(`.codex-plugin` + `skills`),杂物 5.8M,其中 `.git` 独占 2.2M,其余是 `.claude`(研究材料 + ThirdParty + docs)、`.claude-plugin`、`.opencode`、别家清单、`hooks`、`scripts`、根级文档等。(实测)

### 排查命令

```bash
# codex cache 里 SKILL.md 的版本(hash)
sha256sum ~/.codex/plugins/cache/superagents-dz/superagents/*/skills/constitution/SKILL.md

# 跟 github/HEAD 版本比对
git -C /d/superagents show HEAD:skills/constitution/SKILL.md | sha256sum

# 第一层 marketplace 是否重 clone 过、何时(看 clone 时间戳)
cat ~/.codex/.tmp/marketplaces/superagents-dz/.git/logs/HEAD

# 第二层 cache 目录时间戳(重 clone 会刷新)
stat -c '%y' ~/.codex/plugins/cache/superagents-dz/superagents/0.2.0
```

## 四、踩坑清单

| # | 现象 | 根因 | 状态 |
|---|------|------|------|
| 1 | codex 读的是旧版正稿,`sync.mjs` 刷了不生效 | codex 认 github,本地 sync 的改动被会话启动时的重 clone 覆盖 | 已认清:开发时 codex 要走 commit(见五) |
| 2 | `install.mjs` 的白名单清理对 codex 白费,还可能帮倒忙 | 清完 61K,codex 一有更新重 clone 就打回 5.9M;且 `CODEX_KEEP` 把 `.git` 也删了,而 codex 靠 `.git` 认版本,删了下次大概率直接重 clone(**推测**,未单独实测) | 建议去掉 codex 的 keepOnly、保留全量含 `.git`,见「六、未决」 |
| 3 | 新机器装 CC 报 SSH host key 错误 | `buyi1net/superagents` 短格式被 `claude` 当 SSH 解析,新机缺 host key 就失败 | 已修:`install.mjs` 改用完整 HTTPS URL(commit `7c2d751`) |
| 4 | 卸载后 cache 目录还在、重装撞旧文件 | `plugin uninstall` / `marketplace remove` 只删注册,不删 cache 实际文件 | 已修:`install.mjs` 卸载加 `rmDir` 手动清 cache + marketplace 残留 |
| 5 | codex `exec` 下总纲没注入、hook 没跑 | `exec` 是精简 headless 模式,不触发 SessionStart hook,也不做 plugin 同步 | 已知:codex 注入靠 skill 引用不靠 hook;`exec` 场景注入本就受限 |
| 6 | Linux 上 codex `exec` 读不了 skill 文件 | codex 沙箱(bubblewrap)需 Linux user namespace,测试机内核受限、挡住文件读取 | 已知:Linux 以 CC + opencode 为主,codex 不深挖 |
| 7 | opencode 缓存有一堆用不到的杂物(3.8M) | opencode 按 git 依赖拉整仓,bun 又默认不跑 postinstall,没法在拉包时清 | 已知:装完补跑 `clean-opencode.mjs` 清到 66K |
| 8 | 往独立 skill 目录下发会造成 duplicate | `sync-skills` 是 plugin 化前的老下发机制,刷独立 skill 目录会跟 plugin cache 里同一份撞车 | 已删:开发同步改用 `sync.mjs`(本地两家)+ `install.mjs`(从 github),见五 |

## 五、开发同步的两个入口

改了 `skills/constitution/` 正稿后,两个入口各管一段:

**入口 1 —— `node scripts/sync.mjs`(本机快速预览,只刷 Claude Code + OpenCode):**
- 直接覆盖这两家的本地 cache,秒级生效、免提交,开发迭代时快速验它俩遵不遵守。
- 不含 codex:codex 认 github、会话启动会重拉覆盖,本地 sync 对它是无用功。跑 `sync.mjs --codex` 只给提示、不动手。

**入口 2 —— `git commit + push` 再 `node scripts/install.mjs`(从 github 更新本机三家):**
- 先手动 `commit + push` 把正稿推上 github(定稿你掌控,脚本不代劳)。
- 再跑 `install.mjs`,它靠 `marketplace remove + add` 从 github 重新拉、更新本机三家。codex 靠这个才拿到新版(或等它自己下次开会话重拉)、换机器也靠它一键更新。
- opencode 这步会删旧缓存包、触发下次运行重拉最新(bun 缓存钉版本,不删就一直用旧的)。

一句话:**sync 管"快"(本地两家即时预览),commit+push 配 install 管"真·跨机 + codex"(从 github 更新)。** 前者开发迭代用,后者定稿或换机时用。

## 六、macOS 接手验证清单

> 换到 mac 后,让 agent 对着这份逐条验,不用人肉记。每条给了"怎么验 + 算通过的标准"。
> 前提:mac 上路径都在 `$HOME` 下、跟 Windows 同构(`~/.claude`、`~/.codex`、`~/.config/opencode`、`~/.cache/opencode`),脚本用 `os.homedir()` 跨平台,理论上直接能用——但没在 mac 实跑过,逐条验,留意路径和 CLI 命令有无平台差异。
> 进度:Windows 已全绿,Linux 此前过了安装与注入,mac 是最后一块。

### A. 安装

1. `node scripts/install.mjs`(照 README 第一步)。
   - 通过:`~/.claude/plugins/cache/superagents-dz/`、`~/.codex/plugins/cache/superagents-dz/` 出现;`~/.config/opencode/opencode.json` 里写进了依赖。
2. opencode 补清缓存:先正常用一次 opencode 触发拉包,再 `node scripts/clean-opencode.mjs`。
   - 通过:opencode 缓存包从约 3.8M 清到约 66K。

### B. 三家开场注入

3. 新开 Claude Code 会话:constitution 有没有 hook 注入(开场带规则总纲、称"老大")。
4. 新开 OpenCode 会话:constitution 有没有 transform 注入(首条消息带总纲)。
5. 开 codex TUI,问"现在高效交流准则是什么":能答出定稿版(核心目标 / 对话深度 / 少废话 / 别堆砌 / 别过简)就说明 skill 引用读到了。

### C. 本机开发同步(sync.mjs)

6. 改一处 `skills/constitution/` 正稿,`node scripts/sync.mjs`。
   - 通过:CC + opencode 的 cache 里 SKILL.md 变成改后的(`sha256sum ~/.claude/plugins/cache/superagents-dz/superagents/*/skills/constitution/SKILL.md` 跟工作区比一致);跑 `sync.mjs --codex` 只给提示、不刷。

### D. 从 github 更新(install.mjs 重跑)——重点验 opencode 清缓存

7. 随便 commit + push 一处改动,跑 `node scripts/install.mjs --opencode`。
   - **这步 Windows 上只静态验过(语法 + 找包),没端到端实跑;mac 上重点盯:** install 删掉 opencode 旧缓存包(`rmOpencodeCache`)→ 下次运行 opencode 从 github 重拉 → 读到新版。
   - 排查:`ls ~/.cache/opencode/packages/superagents@git*`(install 后应被删,重跑 opencode 后重建为新版)。
8. codex 从 github 更新:push 后开一次 codex TUI,验它自动重 clone 拉新版。
   - 通过:`cat ~/.codex/.tmp/marketplaces/superagents-dz/.git/logs/HEAD` 里 clone 时间戳刷新、cache 的 SKILL.md = github 最新。

### E. 未决决策(mac 验完再拍)

9. **codex 的 keepOnly 去留。** 现在 `install.mjs` 对 codex 做白名单清理(删 `.git` 等、只留 61K)。mac 验时观察:装完 cache 状态、开一次 codex TUI 后是否被重 clone 打回 5.9M 全量。据此定:留全量含 `.git`(建议,理由见四·坑 2)还是继续清。
10. **(可选,不影响用)删 `.git` 是否触发 codex 重 clone。** 从"05:41 有 `.git` 且一致就不重 clone"反推的推测。想钉死:keepOnly 删掉 `.git`、github 保持一致、开 TUI 看是否重 clone。

## 附:治本方向为何走不通

想让 codex cache 别那么臃肿,几条路都堵着:

- **sparse 拉取**:codex `plugin add` 会二次完整 clone,不支持 sparse(partial clone 缺 blob 会失败)。
- **shallow 克隆**:clone 深度是 codex 自己控的,改不了。
- **更新后自动清理**:codex 自动重 clone 没给外部留清理钩子,插不进去;且 `.git` 不能随便清(它靠这个认版本)。

结论:codex cache 全量 5.9M 是它机制决定的,接受比跟它较劲省心。
