## 给 Agent

1. 本目录只存放用于查看、研究、比较、核验、举证、学习或借鉴的外部材料；项目自有成果、正式输入和交付内容不放在这里；
2. 先读同级目录的 [README.md](./README.md)，并只打开本次任务涉及的参考说明文件；
3. 禁止无差别读取全部项目，避免占用上下文。

## 新增参考

1. 按实际用途选择分类；本项目分类名称使用简体中文，已有中文分类继续沿用；
2. 每个参考项单独建立文件夹，名称优先使用来源原名，不散放在参考目录根部；
3. 按要求在 `README.md` 对应分类中增加索引；
4. 写 `参考说明.md`：来源、固定版本或快照、核验日期、许可证、生命周期（`使用中`/`仅证据`/`已废弃`）、内容类型和实际参考范围。

## 拉取副本

1. 先区分临时下载与长期副本；仅供本次查看的下载物放在临时目录，不作为参考副本入库；
2. 确有长期核验或反复使用价值时才保存本地存档，并按来源类型固定可复核的版本或快照；Git 项目记录固定提交，不跟随浮动分支；
3. 同一内容的原始文件和转换全文没有各自独立用途时，不得同时长期保留；
4. `参考说明.md` 补“本地存档”小节：位置、版本或快照、获取日期、用途、更新方式和入库策略；
5. 更新 `README.md` 的当前状态和实际分类说明；
6. 控制存储和上下文占用；不要为了“拉取”而拉取，也不要为了节约空间而放弃确有用途的副本。

## 更新副本

触发条件（满足其一即可）：

1. 项目进入参考版本锁定或升级评估，需要对照新的固定版本或快照；
2. 来源发布与当前项目有关的重要修订或安全更新；
3. 参考说明记录的版本或快照与项目实际采用的参考依据不一致。

更新步骤：取得新的固定版本或快照 → 更新参考说明的版本、核验日期与受影响的结论 → 更新 `README.md` 的当前状态和实际分类说明 → 若结论影响项目正式文档，同步更新对应正文。

## 废弃原则

1. 确认项目不再使用该参考项当前记录的用途、结论或版本；
2. 将`参考说明.md`的生命周期改为“已废弃”，记录日期、原因和最后参考的版本或快照；
3. 删除本地存档，保留参考项文件夹和参考说明；
4. `README.md` 中保留该参考项，在名称后标记“已废弃”；
5. `README.md` 入口中的本地存档改为“已删除”，继续保留参考说明和来源定位信息。

Agent 不得删除 `README.md` 中的参考项记录、来源链接或其他来源定位信息。本规范不提供删除这些记录的流程。

来源重新出现参考价值时，重新核验并更新参考说明；按需恢复本地存档，将生命周期改回“使用中”，再更新 README 的名称和入口。

## 状态约定

1. 核验日期只表示所见事实，不构成跟随来源更新的义务；不触发更新条件就保持固定版本或快照。
2. 来源的版本、描述、数量和发布日期等信息可能变化，正式结论必须注明核验日期。

## 维护原则

1. 不复制参考索引、动态数量、单项资料详情或整份治理规范，参考项的信息只在 `README.md` 维护。
2. 也不得把本次使用的命令、工具、脚本和临时选择写成长期要求。
3. 项目上级 `AGENTS.md` 只增加参考材料治理的触发条件和本文件链接，不得用本示例覆盖或重写。
4. Agent 有责任控制该文件大小，防止小窗口模型瞬间撑爆上下文，但仅限于删除重复内容、动态信息、单项资料详情和一次性操作步骤。

## 版本控制

1. 项目尚未使用版本控制时，不代表本章不适用。
2. 项目尚未使用版本控制时，不得为了本规范自行初始化仓库。
3. 项目使用版本控制时，参考目录根部的 `README.md`、`AGENTS.md` 和 `CLAUDE.md` 属于项目治理文件，由本项目自己的仓库跟踪。
4. `参考说明.md` 放入来源仓库工作树时，必须写入该仓库的 `.git/info/exclude`；不得修改上游 `.gitignore`，也不得提交到来源仓库。
5. Git 参考项目可以直接放在参考项目录。来源仓库的 `.git` 只用于拉取、核验和更新来源版本，不属于本项目的版本控制。
6. Git 参考项目应固定在参考说明记录的提交，工作树不得残留临时修改、生成物或未排除的项目自有文件。
7. 未获用户明确要求，不得在来源仓库创建 commit、push、修改远端，也不得将其作为 submodule、gitlink 或普通项目文件提交到项目仓库。

## 维护结果验收

每次新增、拉取、更新、废弃或调整本目录后，必须在向用户报告结果或结束任务前，重新读取实际文件并逐项验收。

**验收条目：**

1. 收录内容符合参考材料边界，没有混入项目自有成果、正式输入或交付内容。
2. 所有参考项都已分类，没有散落在参考目录根部。
3. 已废弃参考项仍保留参考说明、索引记录和来源定位信息。
4. 每个参考项都有参考说明，来源和实际参考范围可以重新核验。
5. 每段内容至少能帮助人类或 Agent 判断、定位、核验或维护资料；对两者都没有实际用途的内容已经删除。
6. 标题、层级和阅读顺序清楚，摘要与详细内容分开，读者无需加载与当前任务无关的长篇内容。
7. `README.md` 中的数量、分类、状态和链接与磁盘现状一致，项目内链接可以打开。
8. `README.md` 面向人类提供清楚的判断和查找入口，没有混入 Agent 操作步骤。
10. `AGENTS.md` 和 `README.md` 是否存在无限膨胀的可能，如果存在询问用户如何处理。
11. `README.md` 和 `AGENTS.md` 能相互打开，双方各司其职，让其它空上下文的 Agent 可以仅凭该文件也能安全维护。
13. 确保没有机械生成的完整正文副本或无独立用途的重复格式以及大文件已记录按需读取方式。
14. 确保临时文件没有被索引或参考说明依赖，没有作为长期副本入库。
15. 确保每份长期副本都有实际用途，已保存的长期副本没有在临时目录留下重复文件，本次任务的抓取物已经处理完毕。
