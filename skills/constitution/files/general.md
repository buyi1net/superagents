# 文件治理：通用规则

本规范适用于所有会读取、创建、修改、移动、重命名或删除文件的任务。具体场景如果有更专门的文件结构规范，还必须同时遵守该场景规范。

## 制度目的

本规范只解决四件事：让项目可导航、文件可归属、生成物可重建、工作可交接。新 Agent 不得依赖历史对话推断制度目的；遇到具体落点时，按本文件的术语和判定顺序执行。

## 术语和判定

- 项目根目录：当前任务的默认读取、搜索、执行和写入边界；根目录外的内容不自动纳入项目地图。
- 导航引用：用于让读者找到项目内文件或目录的地图、索引、职责表、正文交叉引用和目录树。导航引用必须可点击。
- 命令示例：只展示命令语法、参数或示例输入的代码；其中的路径可保留代码格式，但不得用命令示例代替项目地图。
- 运行数据：程序运行后产生或持续更新的数据库、用户数据、日志、缓存、上传文件和截图；它们不是源码、文档或构建产物。
- 生成文件：可以由源码、脚本或工具重新产生的构建产物、缓存、中间文件和字节码。
- 临时文件：清空后不影响项目实质内容的日志、截图、下载文件、实验文件和 Agent 工作文件。
- 不能确定文件属于哪一类时，先暂停写入，按“自有文件/外部资料/运行数据/生成文件/临时文件”重新判断，不得用模糊目录兜底。
- 判定顺序：先判断文件类型和生命周期，再判断是否属于某个交付项目，最后决定目录和是否需要导航；本规范的明确条款优先于语言、框架或开源项目的常见惯例。

## 文件归属

- 新增、移动或恢复任何文件前，先根据长期用途判断归属，再决定落点；不得因为当前只有一个文件就跳过归类。
- 文件应放在能够长期表达其用途的目录中，不得用“临时”“杂项”“其他”等模糊位置掩盖尚未完成的归类。
- 日志、截图、下载文件、中间文件、缓存、实验产物和 Agent 工作文件必须放入可删除的临时位置，不得直接散放在项目或工作区根部。
- 无法判断文件归属时，先暂停写入并报告，不得随意放入临时目录或任意现有目录。
- 外部资料、上游项目和第三方副本必须与当前项目自有文件区分，不得因为它会被查看、修改或构建就冒充自有文件。

## 文件和路径边界

- 当前项目或工作区根目录是默认的读取、搜索、执行和写入边界；边界外的文件和目录不属于当前文件地图。
- 项目外部路径的访问、复制、移动、修改和创建，遵守 constitution 的全局边界与授权规则；不得把边界外内容登记成项目内文件。
- 用于导航、说明、索引或清单的文件，引用项目内文件或目录时使用相对路径；外部资源使用完整 URL。
- 文件格式支持超链接时，导航引用中的项目内文件或目录必须使用原生可点击相对链接，且链接目标必须实际存在；不支持超链接时，至少写出项目根内的相对路径。
- 代码块中的目录树只能作为辅助示意，不能作为唯一项目地图；真正的地图必须用可点击的目录条目或列表表达。命令示例中的路径不要求链接，但不因此获得导航豁免。

## 根目录文件

- 根目录只保留项目或工作区入口、治理文件，以及工具链强制要求位于根部的配置文件。
- 业务内容、日志、报告、截图、下载资料、临时脚本和 Agent 运行记录不得直接写入根目录。
- 根目录已有文件不代表同类新文件都可以继续放在根目录；新增文件仍须按长期用途重新判断。

## 入口和地图

- `README.md`、`AGENTS.md`、`CLAUDE.md` 和其他入口文件必须各自承担明确职责，不得把入口文件当作动态状态表、交付日志或完整文件清单。
- `AGENTS.md` 只负责路由；项目说明、目录用途和当前实际地图由相应的 `README.md` 或专门文档维护。
- `CLAUDE.md` 是兼容 Claude 的路由入口；存在或因工具链要求创建时，只能使用相对链接指向同级 `AGENTS.md`，不得另行维护规则、地图、状态或交付说明。`CLAUDE.md` 与 `AGENTS.md` 冲突时，以 `AGENTS.md` 为唯一项目路由。
- 每个由人长期维护、用于承载项目内容或独立工作职责的目录，都必须有本目录的说明文件，默认命名为 `README.md`；说明文件写清本目录用途和直接子目录地图。工具链生成目录、版本控制目录和可随时删除的纯缓存目录不要求人工说明，但必须由上级入口标明其可重建或可删除属性。
- 地图只记录当前实际存在、且对读者有导航价值的直接目录；制度允许但尚未创建的目录不得伪装成当前结构。
- 地图不得展开整棵文件树或把每个文件都列成清单；需要说明文件职责时，使用可点击的局部索引。
- 地图按目录逐层接力：小项目不必展开到文件级，大项目由各级目录的说明文件分别维护自己的直接子目录；不得用根目录一张深树替代下级目录说明。
- 入口和地图不得用整棵文件树覆盖并行修改，也不得用过期内容掩盖实际结构。

## 文件变更

- 修改文件前，先重新读取当前内容，确认没有新的并行修改；不得用旧内容整体覆盖用户或其他 Agent 的改动。
- 文件创建、移动、重命名或删除完成后，重新检查受影响的入口、地图和引用。
- 新建、移动或重命名人工维护目录时，必须同时创建或更新该目录的说明文件；删除目录时，必须同步更新最近上级地图。
- 检查引用时，同时检查链接格式和目标存在性；发现纯文本路径承担导航作用时，必须改为相对链接或报告未完成。
- 发现实际文件结构与入口记录不一致时，先判断差异来源；无法判断时保留现状并报告，不得擅自重写地图。

## 临时文件和生成文件

- 临时文件必须可以随时删除，清空后不得造成项目或任务的实质损失。
- 工具链生成的缓存、中间产物和构建目录应配置到可重新生成的位置或纳入忽略规则，不得当作正式源文件维护。
- 任何正式流程不得依赖只能在临时目录或生成目录中找到的唯一文件。

## 规范保护

- 本规范由用户维护。除非用户明确要求，Agent 不得修改、移动、删除、压缩或放宽本规范。
- 发现本规范与任务要求或已有文件冲突时，先报告冲突和影响，不得通过修改规范或入口文件绕过约束。
