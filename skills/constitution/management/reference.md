# 参考材料治理规范

参考材料：从外部收集的、对当前工作有参考价值的完整项目、文献、素材、案例或样例。本规范定义其分类、记录、维护与清理方式；常见场景给出参考分类，其他场景按骨架自行套用，不作强制限定。

## 一、全局优先级

本规范任何条款与实际冲突时，按以下顺序从高到低裁决：

0. 用户规定优先于本规范 — 用户对参考材料管理有明确要求的，按用户要求执行；用户没有此类规定的，按本规范执行；
1. 现状优先于预设 — 已有目录、分类和记录保留，不推倒、不强行改名；用户表示现有内容乱、需要整理时，改按本规范预设整理，无须再确认；
2. 硬逻辑优先于示例 — 本规范的骨架（分层、记录、维护）不变，叫法、语言、形式可随场景调整；
3. 项目语言优先于示例语言 — 命名语言跟随项目主体；
4. 原名优先于翻译 — 参考项名称用来源原名；
5. 主要用途优先于次要用途 — 跨类材料按主要用途归类，次要用途写进说明。

## 二、通用约定

- 语言：目录名、分类名、说明文件名跟随项目主体语言；参考项文件夹名用来源原名，不翻译。
- 命名：用表达“参考”“说明”含义的常用词（如中文「参考资料」、英文「reference」、日文「参考資料（さんこうしりょう）」、韩文「참고자료」）；自行命名时说人话、不造抽象词。
- 按需创建：用不到的分类不建文件夹，不预建空目录，不凑数。

## 三、目录结构

```
<参考目录>/
├── README.md          # 路由与维护手册
├── <分类名>/
│   └── <参考项名>/
│       ├── <说明文件>   # 如「参考说明.md」
│       └── （本地副本，如有）
```

**目录与命名**

- 目录名不固定，跟随已有现状与用户偏好等设定；语言与命名规则见通用约定。
- 已有目录名一律沿用，不强制改名；用户表示内容乱、需要整理时除外（见全局优先级第 1 条）。
- 识别参考目录看内容（外部参考材料与索引说明），不看名字。

**参考项与说明**

- 每个参考项一个文件夹，说明与副本同居，整体可移动、归档、删除。
- 说明文件避开 README.md（与来源方自带 README 冲突），中文可用「参考说明.md」；它是该参考项的唯一权威正文。
- 参考说明必填字段：来源、完整来源地址、固定版本或快照、核验日期、许可/版权、生命周期、内容类型、实际参考范围。
- 内容类型按材料性质写（框架、文献、模板、素材、案例等），不设固定枚举，同一项目内保持一致。
- 有本地副本时补：位置、获取日期、更新方式。
- 本地副本：按固定版本或快照获取，与来源保持一致，不写入自有内容，不跟随浮动版本。

## 四、文件分类

> **骨架（强制）**：参考材料按“离当前工作的距离”由近到远分为五个位置：① 直接依赖 → ② 同源可接入 → ③ 同类对标 → ④ 呈现学习 → ⑤ 兜底。位置是硬逻辑，叫法弹性见全局优先级第 2 条。

**参考分类（非强制，对号入座）**：

| 位置 | 研发 | 办公 | 科研 | 设计 |
|---|---|---|---|---|
| ① 直接依赖 | 核心上游 | 制度依据 | 基础文献 | 设计基线 |
| ② 同源可接入 | 架构参考 | 流程范例 | 相邻工作 | 同体系组件 |
| ③ 同类对标 | 竞品项目 | 同行案例 | 竞争研究 | 对标作品 |
| ④ 呈现学习 | 界面参考 | 版式参考 | 写作参考 | 视觉灵感 |
| ⑤ 兜底 | 其它参考 | 其它参考 | 其它参考 | 其它参考 |

使用规则：

- 选择与当前工作最接近的场景，采用该列分类名；
- 场景不在示例中时，按五个位置自行命名（命名风格见通用约定）；
- 同类材料按主要价值归类（见全局优先级第 5 条）；分类本身即重要级别，不另设重要性字段。

**新项目**：按项目主体性质选最接近的场景列（有源码→研发；制度文档→办公；论文实验→科研；设计稿→设计），作为一级分类；混合场景选一列为主，跨场景材料就近归入，不另建第二套列。

**老项目**：已有分类一律保留；在 README 中把现有分类映射到五个位置，再补齐索引与参考说明；存量不动、新增有序；迁移或改名需用户授权。

## 五、说明文件

主 README 是参考材料目录的唯一入口，固定以下结构，按序排列：

1. **阅读规则** — 置顶：按当前任务相关性选择参考项，禁止无差别读取全部说明或副本。先看到规矩，再看到内容。
2. **当前状态** — 三行内的全局摘要：参考项总数、分类数、本地副本数、最近核验日期。扫一眼掌握全局，状态是摘要不是推论。
3. **分类与结构** — 分层位置与场景示例；参考项文件夹布局；副本存储与同步边界。
4. **项目索引** — 表格五列：参考项 / 参考价值 / 文档 / 本地副本 / 来源。“参考价值”用一句话说明为什么收录，让读者不打开文件即可判断相关性；链接用引用式定义统一收在文末，表格内只放短引用。
5. **维护规则** — 新增、拉取、更新、删除的分步约定。

设计原则：防呆前置（先讲怎么读）、状态可见（全局状态是摘要不是推论）、单一入口（永远一个入口文件）。维护规则较长时可拆到独立文件（如「维护手册.md」），README 只留路由与索引并链接过去，当前规模不必拆。

## 六、维护规则

**新增**：判定分类 → 建文件夹 → 写参考说明 → 索引表加行、文末补链接定义 → 更新核验日期。

**拉取副本**：进入参考项文件夹，按说明中的固定版本或快照获取 → 说明补「本地副本」小节 → 索引「本地副本」列更新（状态、短版本号挂目录链接、日期）。

**更新副本**，满足其一才更新：

- 当前工作进入版本锁定或升级评估，需对照新版本；
- 来源方发布相关重大版本或安全修复；
- 说明版本与当前工作实际锁定的版本不一致。

更新步骤：获取新版本 → 更新说明的版本、核验日期与受影响结论 → 更新索引状态列 → 影响正式文档时同步正文。

**删除参考项**：先清理项目内对该参考项的引用 → 说明生命周期改为「已废止」并留原因 → 删除文件夹、索引行与链接定义。副本无需备份，按来源地址 + 版本可重建。

## 七、状态与约定

- 生命周期：`使用中`（当前依据）/ `仅证据`（只作历史或证据）/ `已废止`（不再参考）。
- 核验日期只表示所见事实，不构成跟随来源方更新的义务。
- 第三方动态数据（Star、描述、数量等）随时变化，结论必须注明核验日期。
- 同步边界：入库的只有主 README 与各参考说明；本地副本不入库（可重建），由忽略规则强制。
- 表格尽量保持列宽对齐（全角字符计 2 格、半角计 1 格），以渲染效果为准，不对齐不影响有效性。
