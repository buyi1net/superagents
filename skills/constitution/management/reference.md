# 参考材料治理规范

参考材料是从外部收集、用于理解、比较、核验、举证、学习或借鉴的外部资料。本规范适用于研发、办公、科研、设计以及其他项目场景；正文中的场景和名称都是使用示例，不限定项目类型。本文件是项目参考材料目录的专用规范，独立定义该目录的维护方式，在参考材料目录的职责和操作范围内，以本文件为准。

## 一、治理目标

1. 用户可以通过参考根目录的说明文件（如 README.md），直观查看和管理全部参考资料；
2. 索引路由到每个参考项的说明文件和本地副本（如有）；
3. 维护规则保证任何 Agent 都能持续维护本目录；
4. 状态字段让用户通过说明文件掌握全局。

## 二、职责边界

**放入参考材料目录：**

- 不属于项目自有成果，只用于理解、比较、核验、举证、学习或借鉴的外部材料；
- 外部项目、制度、标准、文献、研究成果、数据样本、模板、方法、素材、案例和样例；
- 某项正式输入或外部组成部分的说明、快照、分析记录需要留作参考时，可以作为参考项保存，但只承担参考和证据职责。

**不放入参考材料目录：**

- 项目正在产出或长期维护的自有成果、过程记录、正式数据、交付内容和运行内容；
- 当前工作必须直接采用、编辑、加工、执行或随成果一起交付的正式输入与外部组成部分；

## 三、全局优先级

本规范任何条款与实际冲突时，按以下顺序从高到低裁决：

0. 用户规定优先于本规范 — 用户对参考材料管理有明确要求的，按用户要求执行；用户没有此类规定的，按本规范执行；
1. 现状优先于预设 — 已有目录、分类和记录保留，不推倒、不强行改名；用户表示需要整理时，改按本规范预设整理，无须再确认；

## 四、通用约定

- 暂无

## 五、目录结构

```
<参考目录>/
├── README.md          # 路由与维护手册
├── <分类名称>/
│   └── <参考项名>/
│       ├── <说明文件>   # 如「参考说明.md」
│       └── （本地副本，如有）
```

**目录与命名**

- 参考目录：与项目根目录其他文件夹命名语言保持一致，用表达“参考”“说明”含义的常用词（如中文「参考资料」、英文「reference」）；
- 分类名称：详见[文件分类](#六文件分类)；
- 参考项名：优先使用来源原名，不翻译；

- 按需创建：用不到的分类不建文件夹，不预建空目录，不凑数；
- 已有目录名一律沿用，不强制改名；用户表示需要整理时除外（见全局优先级第 1 条）；
- 识别参考目录看内容（外部参考材料与索引说明），不看名字。

**参考项与说明**

- 每个参考项一个文件夹，说明文件和参考项同文件夹存放，要求整体可移动、归档；废弃时只删除本地副本，保留参考项文件夹和说明文件。
- 说明文件避开 README.md（与来源方自带 README 冲突），中文可用「参考说明.md」其他语言同理；它是该参考项的唯一权威正文。
- 参考说明必填字段：来源名称、来源定位信息、固定版本或快照、核验日期、许可/版权、生命周期、内容类型、实际参考范围。
- 来源定位信息按材料实际情况填写完整 URL、DOI、ISBN、标准号、档案号、出版信息、内部位置、提供方或取得方式；有网络地址时使用可点击链接，没有网络地址时填写足以重新定位材料的信息，不得编造地址。
- 内容类型按材料性质写（项目、制度、标准、文献、数据、模板、方法、素材、案例等），不设固定枚举，同一项目内保持一致。
- 有本地副本时补：位置、获取日期、更新方式。
- 本地副本：按固定版本或快照获取，与来源保持一致，不写入自有内容，不跟随浮动版本。

## 六、文件分类

> 参考材料如果不分类，来源、用途和维护边界会随着项目推进逐渐混乱。

**参考分类（非强制，对号入座）**：

| 位置 | 研发 | 办公 | 科研 | 设计 |
|---|---|---|---|---|
| ① 直接依据 | 核心上游 | 制度依据 | 基础文献 | 设计基线 |
| ② 同源可接入 | 架构参考 | 流程范例 | 相邻工作 | 同体系组件 |
| ③ 同类对标 | 竞品项目 | 同行案例 | 竞争研究 | 对标作品 |
| ④ 呈现学习 | 界面参考 | 版式参考 | 写作参考 | 视觉灵感 |
| ⑤ 兜底 | 其它参考 | 其它参考 | 其它参考 | 其它参考 |

**使用规则：**

- 参考分类为示例骨架和示例场景，非强制要求；
- 不论实际工作场景在不在示例范围，Ai 都可以进行自由发挥自由分类；
- 未覆盖的场景按参考材料的实际用途自行分类；拿不准时沿用示例骨架。

**禁止规则：**

- 禁止 Ai 以任何理由，任何借口不做分类处理，哪怕只有一个参考例子都需要做分类；

**场景处理：**

- 新项目：如果没有更好的文件分类方式，就按照本节示例中的五个位置作为一级分类，其他场景自行命名；
- 老项目：已有分类一律保留，补齐 README 索引与参考说明；新增内容沿用现有合理分类；迁移或改名需用户授权。

## 七、说明文件

> 主 README 是参考材料的唯一权威索引与维护手册。索引路由到每个参考项的说明文件和本地副本；维护规则保证任何 Agent 都能持续维护本目录；状态字段让用户凭本文件掌握全局。

1. **阅读规则** — 置顶：按当前任务相关性选择参考项，禁止无差别读取全部说明或副本。先看到规矩，再看到内容。
2. **当前状态** — 三行内的全局摘要：参考项总数、分类数、本地副本数、最近核验日期。扫一眼掌握全局，状态是摘要不是推论。
3. **分类与结构** — 分层位置与场景示例；参考项文件夹布局；副本存储与同步边界。
4. **参考索引** — 按实际分类分组，每个参考项固定写三行：名称、参考价值和入口。“参考价值”用一句话说明为什么收录，让读者不打开说明文件即可判断相关性；“入口”依次提供参考说明、本地副本和来源。参考说明、本地路径以及存在网络地址的来源必须使用可点击链接；来源没有网络地址时，填写足以重新定位材料的来源定位信息。

   ```md
   ### 核心上游
   
   #### cordis
   - 参考价值：DSH 底层插件框架，第一方插件开发的编程载体。
   - 入口：[参考说明](核心上游/cordis/参考说明.md) · [本地副本](核心上游/cordis/)：`8cc9e33f` · 2026-08-14 · [来源](https://github.com/cordiverse/cordis)
   ```

   上述代码块只展示模板。实际 README 必须把三行条目写成普通 Markdown，不能放进代码块；链接直接写在条目中，不另建链接定义。没有本地副本时，入口写“本地副本：未获取”，不创建副本链接。
5. **维护规则** — 新增、获取、更新、废弃和恢复使用的分步约定。

设计原则：防呆前置（先讲怎么读）、状态可见（全局状态是摘要不是推论）、单一入口（永远一个入口文件）。维护规则较长时可拆到独立文件（如「维护手册.md」），README 只留路由与索引并链接过去，当前规模不必拆。

## 八、维护规则

**新增参考项**：判定分类 → 建立参考项文件夹 → 写参考说明 → 在 README 对应分类下新增三行索引条目 → 使用行内链接连接参考说明、本地副本（如有）和存在网络地址的来源；来源没有网络地址时填写来源定位信息 → 更新全局状态。

**获取本地副本**：按参考说明记录的固定版本或快照获取副本 → 将副本放入参考项文件夹 → 在参考说明中记录位置、版本或快照标识、获取日期和更新方式 → 在 README“入口”行增加可点击的本地副本目录、版本或快照标识和获取日期。

**更新参考项**，满足其一时处理：

- 当前工作需要核验来源的新版本或新内容；
- 来源方的修订、勘误、撤回或其他变化会影响现有参考结论；
- 参考说明记录的版本或快照与当前实际参考内容不一致。

更新步骤：核验来源 → 获取新版本或快照 → 更新参考说明中的版本、核验日期、实际参考范围和受影响结论 → 更新 README 中的参考价值和本地副本信息 → 影响项目正式成果时同步修订相关内容。来源链接或其他来源定位信息必须保留。

**废弃参考项**：

1. 确认项目不再把该参考项当前记录的用途、结论或版本作为现行依据；
2. 将参考说明的生命周期改为「已废弃」，记录废弃日期、原因和最后参考的版本或快照；
3. 删除本地副本，但保留参考项文件夹和参考说明；
4. README 中的参考索引必须保留，在参考项名称后标记「已废弃」；
5. README“入口”行中的本地副本改为「已删除」，参考说明链接和来源链接或其他来源定位信息继续保留；
6. Agent 不得删除 README 中的参考项记录、来源链接或其他来源定位信息。

**恢复使用**：来源出现新的参考价值时，重新核验来源 → 更新参考说明中的参考价值、实际参考范围、版本或快照和核验日期 → 按需重新获取本地副本 → 将生命周期改回「使用中」 → 删除 README 名称中的「已废弃」标记并更新入口信息。

本规范不提供删除参考索引记录、来源链接或其他来源定位信息的流程。Agent 只能更新状态，不得从 README 移除参考项或来源。

## 九、状态与约定

- 生命周期：`使用中`（当前仍作为参考依据）/ `仅证据`（只用于保留历史事实或结论依据）/ `已废弃`（当前用途、结论或版本已经停止使用，但参考说明和来源定位信息继续保留，后续可以重新核验并恢复为「使用中」）。
- 核验日期只表示所见事实，不构成跟随来源方更新的义务。
- 第三方动态数据（评分、描述、统计数量、发布状态等）随时变化，结论必须注明核验日期。
- 同步边界：主 README 与各参考说明属于项目正式维护内容；本地副本是否纳入项目正式存储，由用途、授权条件、保存责任和项目存储方式共同决定。未纳入时用忽略或访问规则隔离，纳入时在参考说明中记录原因、范围和维护方式。
