# 工作交接

> 把当前会话整理成**交接快照**:人能快速审阅,下一位 agent 能直接接手。不要回答原问题,也不要继续执行任务。

## 规则

- 只整理可见上下文;不要新调查、改代码、跑测试、提交或访问外部系统。
- 用户传入参数 = 下一位接手者的关注点。
- 如有 `<previous-summary>`,基于最新历史更新:保留有效内容,删除过时内容,合并新信息。
- 不要把 `<previous-summary>` 或 `<handoff-template>` 标签写入最终文件。
- 人要看得懂:目标、进度、决策、风险、待确认项清楚。
- agent 要能接手:路径、命令、错误、上下文、下一步具体可执行。
- 不确定就标"未确认";不要编造路径、URL、issue、commit、命令结果或测试结果。
- 使用简体中文;代码、命令、路径、错误信息保持原文。
- 不泄露 secrets、token、私钥、完整 `.env` 内容。
- 已有 PRD、计划、ADR、issue、commit、diff 中记录过的内容,只引用路径或 URL。

## 模板

严格按以下结构生成并保存:

<handoff-template>

## 目标
- [接下来要继续什么]

## 用户意图与约束
- [目标、偏好、限制;没有则写"(无)"]

## 状态
### 已完成
- [已完成、已确认、已决定;没有则写"(无)"]

### 进行中
- [正在推进但未完成;没有则写"(无)"]

### 未完成 / 阻塞
- [待处理、待验证、待确认;没有则写"(无)"]

## 决策与原因
- [决策:原因;没有则写"(无)"]

## 重要上下文
- [必须保留的背景、边界、错误、历史取舍;没有则写"(无)"]

## 文件与命令
- [路径或命令:为什么重要;结果如有写明;没有则写"(无)"]

## 风险与待确认
- [风险 / 假设 / 待确认;没有则写"(无)"]

## 下一步
1. [最高优先级动作;没有则写"(无)"]
2. [后续动作;没有则省略此行]

## 接手注意事项
- [优先读什么、避免什么、建议使用哪些已知 skill;没有则写"(无)"]
</handoff-template>

## 保存

- 如果项目已经定义了交接目录或者文档目录就直接存进去。
- 如果项目没有定义交接目录和文档目录,就保存到系统临时目录,例如 `$TMPDIR`、`TEMP` 或 `TMP` 指向的位置。
- 文件名:`handoff-<YYYYMMDD-HHMMSS>.md`。
- 写入前检查重名;冲突时追加短随机后缀,例如 `handoff-20250120-143052-a3f9.md`。
- 不覆盖已有文件。

## 回复

保存完成后,只输出真实绝对路径:

```text
Handoff saved to: /absolute/system-temp-path/handoff-<文件名>.md
```

除非用户明确要求预览,不要把交接正文贴到聊天里。
