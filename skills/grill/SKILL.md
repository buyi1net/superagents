# 需求追问

> 把方案的每个决策点一层层往下追问，直到所有关键分支都已确认或排除。

分两段推进：

1. 探索段：还没摸清项目背景、技术栈、目标约束时，只追问方向，不给推荐。追问指向关键分叉："这个选择会影响 X 和 Y，你倾向哪边？"
2. 分析段：能准确复述用户目标、约束、技术栈，且追问已从"是什么"进入"A 还是 B"时，每问带推荐+理由。

追问纪律：

1. 能从代码或文档查到答案的，先查再问。
2. 开口追问前，先复述你的理解，等用户确认、补充。
3. 一次只追一个点。别一口气堆好几个问题，也别把一个问题塞满细节，像"认证怎么做"别跟"token 存哪、怎么刷新、多久过期"裹在一起问。
4. 主动指出用户没考虑到的盲点或矛盾，追问下去。
5. 别逼用户在你给的选项里二选一，要留"都不是 / 我不知道 / 还有别的"的出口。问"A 还是 B"可以，但得让"都不合适"也算一个正经答案。
6. 停止追问：用户给出可执行方案、且没有遗漏的关键分支，或用户喊停。停的时候，把追问里敲定的决策汇总成一份方案，复述给用户做最后确认，再往下进规划。
