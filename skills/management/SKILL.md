# 项目管理

> 全程红线：治理先于内容。先读取项目现有入口并判断工作模式，再决定使用项目内规则还是本 skill 的建设规范；不得先创建、下载、生成、修改、移动或运行主体内容，最后再补治理。

> 项目边界红线：凡为当前项目进行的调研、下载、实验、测试、构建或运行，无论内容是否临时、是否提交版本控制，都属于项目工作；确认项目根后必须优先使用项目根内，或者项目规则、用户明确指定的项目专用位置，不得把系统临时目录当作默认落点。

## 管理目标

本 skill 用于建立、修复和升级项目治理。最终成果不是让项目永久依赖本 skill，而是把边界、入口、场景规则、索引和可重复流程落入项目，使没有加载本 skill、没有会话记忆的空上下文 Agent 仍能自主维护。

项目自治不等于每个目录复制一套规则。项目根入口承担通用边界和场景路由；普通目录继承最近的上级 `AGENTS.md`；只有形成独立治理边界时才建立局部入口。详细场景规则按需读取，不集中堆入项目根入口。

## 项目根判定

在为任务创建、下载、生成或运行任何内容前，按以下顺序确定项目根：

1. 用户明确指定的项目目录优先；用户专门建立或选择某个目录，并让 Agent 在其中开展会形成长期成果的工作时，该目录即使为空也视为项目根；
2. 没有明确指定时，根据当前目录及其上级最近且适用于当前任务的 `AGENTS.md`、版本库边界、项目清单、源码和项目 README 确定，不单凭目录名称猜测；
3. 位于项目子目录时继承所属项目根；存在嵌套项目时按当前任务实际维护的最小完整项目边界确定；
4. 当前位于用户主目录、桌面、下载目录、盘符根、系统临时目录或其它通用位置，且没有以上依据时，项目根尚未确定。只读检查可以继续，需要产生文件或外部副作用时先向用户确认，不得用系统临时目录代替项目根。

## 工作模式

处理项目文件或目录前，先读取项目根及目标位置最近的有效入口，再按实际状态选择一种模式：

| 模式 | 判断条件 | 强制处理 |
|---|---|---|
| **建设** | 新项目、空目录形成长期成果，或既有项目首次出现尚无本地治理的新场景 | 完整读取命中的场景模块，先把治理能力落入项目，再处理主体内容 |
| **维护** | 既有项目已经有能够指导当前任务的项目内入口和场景规则，并满足“自治判定” | 只执行项目内规则；不得为了比较优劣再次加载通用场景模块或套用模板 |
| **修复** | 当前任务暴露出入口缺失、规则无法指导当前操作、链接失效、职责冲突或磁盘与索引不一致 | 完整读取对应模块，只修复当前任务需要的治理缺口；不得借机重塑其它结构 |
| **治理** | 用户要求整理、规范、审计、重构、迁移或评估项目长期维护能力 | 完整读取[项目治理与整理](./modules/governance.md)，在用户指定范围内评估和处理 |

新任务、新文件或新增同类条目不等于新场景。既有制度的结构、名称或写法与本 skill 不同，也不构成修复理由；只要它能够自治并安全支持当前任务，就按维护模式执行。

当前任务只有读取、检查、诊断或验收权限时，发现治理缺口只报告，不得自行进入修复或治理模式扩大写入范围。

## 自治判定

项目内治理只有同时满足以下条件，才可进入维护模式：

1. 空上下文 Agent 从项目根入口能够判断项目边界、当前任务入口及需要读取的项目内规则；
2. 命中具体场景后，能够仅凭项目内文件确定内容归属、生命周期、操作顺序和直接维护位置；
3. 能够知道何时更新 README、Agent 入口、索引、说明、脚本或配置，不依赖任务结束后的补整理；
4. 能够处理当前场景的新增、修改、移动、清理和验收，并识别需要用户授权的操作；
5. 项目内链接能够打开，规则与磁盘一致，且不把本机缓存、外部 skill、某台电脑的绝对路径或前序会话作为唯一依据。

只写“加载 management”或链接外部规则不算自治。固定顺序能够由脚本、配置或自动检查可靠保证时，项目入口只需说明执行入口和失败边界，不复制实现细节。

## 执行顺序

1. 确认用户要求、写入权限和不可改变的范围，并按“项目根判定”确认工作边界；
2. 读取项目根入口、目标位置最近的入口及本次任务直接需要的说明，不无差别扫描整个项目；项目根已确定后，调研、试验和验证产生的内容也必须纳入该项目边界；
3. 按“工作模式”和“自治判定”确定建设、维护、修复或治理模式；
4. 逐条检查“内容与场景索引”。维护模式读取项目内场景规则；建设和修复模式完整读取命中的模块；治理模式先执行治理模块，只对确认需要调整的场景继续读取专用模块；
5. 在当前层治理成立后处理主体内容。工具输出位置必须事先确定，不得接受错误落点后再搬运；
6. 结构、职责、入口或索引发生变化后，立即维护直接上级入口并重新核验，再继续其它主体工作；
7. 完成后同时核对执行顺序、最终磁盘和空上下文自治能力。

## 内容与场景索引

> 全程红线：不分阶段，看意思不看词。必须逐条检查下列触发条件。命中后，维护模式必须先读取并执行项目内已经成立的场景规则；建设和修复模式必须在主体工作前完整读取对应模块；治理模式只读取已经确认需要调整的场景模块。不得用本文件摘要代替模块正文，也不得在合格老项目中无理由重复加载建设模块。

### 项目治理与整理

**触发与强制措施：** 凡用户要求整理、规范、治理、审计、重构、迁移目录或规则，或者评估项目能否长期维护、能否由空上下文 Agent 自主接手，必须在检查或改变指定范围前完整读取并执行[项目治理与整理](./modules/governance.md)。普通文件操作不得自行扩大为全项目治理。

### Agent 入口

**触发与强制措施：** 凡任务涉及 `AGENTS.md`、`CLAUDE.md` 中任意一个文件的创建、迁移、修改、移动、重命名或验收，必须在处理其中任意一个文件前完整读取并执行 [Agent 入口治理](./modules/agent-entry.md)。

### 归档内容 - archive

**触发与强制措施：** 凡任务涉及让旧版本、旧方案或阶段成果退出当前流程但继续保留，或者对已有归档内容进行迁移、压缩、索引、恢复、清理、引用或验收，必须在确定归档位置或开始处理前认定为归档场景；建设、修复，或治理模式确认需要调整本场景时，完整读取并执行[归档治理](./modules/archive.md)。

## 项目内落地底线

- 新建项目、空目录形成长期成果或既有项目没有有效根入口时，先按[Agent 入口治理](./modules/agent-entry.md)建立项目根入口；根入口完成只代表项目根成立。
- 首次建立场景时，命中模块必须把长期有效的边界、路由、操作顺序和维护方法落入项目内稳定文件；不得只留下本 skill 的路径。
- README 面向人说明用途、边界、当前事实和阅读入口；`AGENTS.md` 面向 Agent 说明开工前必须知道的长期规则与场景路由；详细正文各归其位，不互相复制。
- 普通目录继承最近的上级 `AGENTS.md`。只有用户、既有项目或场景模块认定为独立治理边界时才建立局部 Agent 入口，不为每个子目录机械复制规则。
- 既有项目优先沿用已经能够自治的结构、命名和说明来源。缺口修复只补实际缺失能力，除非用户明确要求迁移到标准模板。
- 同一职责只保留一个主要说明来源；项目内使用稳定相对链接，索引只记录实际存在且有导航价值的内容。

## 完成验收

结束前重新读取实际文件并确认：

1. 工作模式选择有事实依据，没有把普通维护扩大为治理，也没有让新项目或新场景跳过建设；
2. 主体内容开始前，当前层已经具备足以指导本次工作的入口、归属和场景规则；
3. 结构、职责、入口或索引变化后，在继续其它主体工作前完成了直接上级维护；
4. 正式内容、参考材料、源码、测试、运行数据、生成物、临时物、归档物和最终交付物没有混放；
5. 项目内入口、说明、链接和磁盘一致；没有加载本 skill、没有前序上下文的 Agent 仍能从项目根自主完成同类维护。

最终文件齐全只能证明最终状态，不能证明开工门禁和即时维护曾按顺序执行。缺少顺序证据时不得声称对应门禁通过。
