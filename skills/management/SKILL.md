# 项目管理

> 全程规则：先理解项目边界、文件归属和现有约定，再读取、创建、修改、移动、重命名或删除文件。任务命中专用模块时，完整读取对应模块后再继续；不得用本文件的摘要代替模块正文。

## 开始工作

按本次任务实际涉及的范围确认以下事实，无关项不为满足检查而创建：

1. 当前工作边界在哪里，当前目录是否为项目根目录；
2. 当前工作属于新项目、既有项目，还是尚未形成长期成果的临时任务；
3. 项目已有的入口文件、目录说明、内容索引、适用规则和稳定约定；
4. 本次会读取或改变哪些文件，哪些入口、索引、链接、构建或交付内容会受影响；
5. 本次读取、新增或取得的内容命中“内容与场景索引”中的哪些条目；
6. 内容是否需要长期维护、重复使用、交接或交付，能否由源码、脚本或工具重新生成。

既有项目优先沿用已经成立的结构、命名和说明来源。不得为了套用本规范而搬动原有内容、重建目录、强制改名或复制已有说明。无法确定工作边界、内容归属或生命周期时，保留现场并向用户说明缺口，不得先写入再补判断。

## 项目入口、索引和链接

项目形成需要持续维护的文件后，在项目根建立以下入口：

| 入口        | 职责                                                 |
| ----------- | ---------------------------------------------------- |
| `README.md` | 面向人说明项目用途、使用方法、当前实际内容和阅读入口 |
| `AGENTS.md` | 面向 Agent 说明长期工作边界、适用规则和读取入口      |
| `CLAUDE.md` | 将 Claude Code 路由到同级 `AGENTS.md`                |

已有等效入口时，先确认各自职责，不得机械新增重复说明。Agent 入口的内容和迁移方式以[内容与场景索引](#内容与场景索引)中对应条目指向的规范为准。

- 项目根和实际创建并承载人工维护内容的一级目录使用 `README.md` 作为主要说明入口。README 至少说明所在层级的作用、边界、当前实际直接内容，以及必要的使用方法或进入路径。
- 二级及更深目录不新增项目治理用的 `README.md`。需要说明时，使用最近的一级目录 README、项目文档或已有说明文件；外部项目原本自带的 README 可以随原项目保留，但不得当作本项目新增说明的模板扩散。
- 目录索引只记录当前实际存在、对读者有导航价值的直接内容，不预写尚未创建的目录，也不使用完整文件清单或整棵目录树代替阅读路径。
- 人工维护目录或其直接内容发生新建、删除、移动、重命名、职责变化或入口变化时，同步更新直接包含它的上一级索引。只修改正文且没有改变职责、入口或索引内容时，重新确认索引仍然准确，不机械改写。
- 支持链接的文档中，项目内导航使用可点击的相对链接，外部资源使用完整 URL。链接目标必须实际存在；代码块中的目录树和命令参数不能代替导航链接。

## 目录和内容

- 只在已有实际内容或职责已经确定时创建目录，不预建空目录、空分类或无用途层级。
- 一个目录只承担一个明确的主要职责、项目边界或生命周期。文件按用途和职责归类，不按扩展名机械堆放。
- 同一任务或独立职责的材料集中存放。多个独立主题长期共存且读者需要分别进入时，再建立分类目录；内容规模很小且无需分别导航时，可以保留在上级目录并由上级说明交代。
- 文档按阅读主题归类，脚本按操作用途归类，测试按性质和范围归类，设计材料按设计意图归类。说明文件、工作记录、日志、截图、缓存、构建物和临时物不得互相混放。
- 生成物必须可重建，临时物必须可删除。需要长期保留的 Agent 产物仍按实际用途归入正式内容，不得仅因由 Agent 生成就放进临时区。
- 同一职责只保留一个主要说明来源。入口之间通过链接分工，不复制正文，不把动态状态、实时日志和单次任务进度写成长期规则。

## 内容与场景索引

开始工作前和执行过程中检查全部条目。条目可以同时命中；命中多个条目时，执行全部处理要求，并完整读取所有对应模块。模块要求继续读取、参照或对照其它文件时，不得用摘要、旧对话或记忆代替原文。

### 项目自有内容

**对象：** 项目正在产出或长期维护的源码、文档、规则、脚本、测试、正式数据和成果。
**边界：** 不包括只供参考的外部材料、运行数据、生成物、临时物和独立交付物。
**处理：** 放入项目既有或已确认的职责边界，纳入相应入口和维护流程。
**触发：** 读取、创建、修改、移动、重命名或删除这类内容时。
**规范：** 执行本文件和项目已有规则。

### 正式源码

**对象：** 项目自有的业务源码、可维护技术包和独立交付单元。
**边界：** 不包括完整外部上游项目、参考副本、自动化脚本、项目级测试、运行数据和工具链生成目录。
**处理：** 纳入明确的源码边界，维护源码区总览、直接子项目职责、主要入口以及运行和测试方式。
**触发：** 确定源码位置，或者读取、创建、修改、移动、重命名、拆分或验收源码内容时。
**规范：** 完整读取并执行 [源码治理](./modules/source.md)。

### 长期项目文档

**对象：** 项目长期维护的使用、技术、架构、决策、计划、交付和运维文档。
**边界：** 不包括视觉设计源文件、业务源码、外部参考副本、临时报告和实时日志。
**处理：** 按读者的阅读目的和文档主题组织，维护简体中文入口、分类和导航。
**触发：** 创建、修改、分类、移动、重命名、索引或验收这类文档时。
**规范：** 完整读取并执行 [项目文档治理](./modules/docs.md)。

### 视觉与交互设计材料

**对象：** 原型图、交互原型、UI 设计系统、设计令牌、组件规范和原型验证资料。
**边界：** 不包括架构文档、技术文档、普通项目文档、正式业务源码、运行数据和构建包。
**处理：** 按设计意图集中管理，与正式源码、长期文档和临时导出物分开。
**触发：** 创建、收集、修改、分类、移动、导出或验收这类设计材料时。
**规范：** 完整读取并执行 [设计材料治理](./modules/design.md)。

### 可重复执行脚本

**对象：** 可重复执行的构建、测试、部署、迁移、校验和数据处理脚本。
**边界：** 不包括业务源码、正式测试和不可重复的一次性实验脚本。
**处理：** 按操作用途归类，并说明输入、输出、副作用、前置条件和运行方式。
**触发：** 创建、修改、分类、移动、执行、交接或验收这类脚本时。
**规范：** 完整读取并执行 [脚本治理](./modules/scripts.md)。

### 项目级测试

**对象：** 跨子项目或跨模块的集成、端到端、回归、验收测试和公共测试数据。
**边界：** 只验证单个模块且不启动真实服务的单元测试属于对应源码单元，不属于项目级测试区。
**处理：** 按测试性质和范围归类，说明运行方式、依赖、产物位置以及清理或保留规则。
**触发：** 创建、修改、分类、移动、运行、交付或验收这类测试和测试数据时。
**规范：** 完整读取并执行 [测试治理](./modules/tests.md)。

### 归档内容

**对象：** 已经废弃、退出当前流程，但仍需长期保留以便追溯的旧版本、旧方案和阶段成果。
**边界：** 不包括当前流程仍需使用的内容、临时备份、实时日志和未完成材料。
**处理：** 与当前内容分开，记录版本、归档原因、替代关系和恢复状态，默认只读。
**触发：** 归档、迁移、压缩、索引、恢复、清理或引用这类内容时。
**规范：** 完整读取并执行 [归档治理](./modules/archive.md)。

### Agent 入口

**对象：** `AGENTS.md`、`CLAUDE.md`。
**边界：** `README.md` 和普通项目文档不属于 Agent 入口；同级两个入口文件作为一组管理。
**处理：** 保持 `AGENTS.md` 为唯一入口正稿，`CLAUDE.md` 只负责固定路由。
**触发：** 创建、迁移、修改或验收其中任意一个文件时。
**规范：** 完整读取并执行 [Agent 入口治理](./modules/agent-entry.md)。

### 外部参考材料

**对象：** 仅用于查看、研究、比较、核验、举证、学习或借鉴的外部项目、文档、标准、数据、模板、素材和样例。
**边界：** 需要直接采用、编辑、加工、执行或随成果交付的外部内容不属于参考材料。
**处理：** 与项目自有内容分开，记录来源、固定版本或快照、实际用途和生命周期。
**触发：** 收录、分类、拉取、更新、废弃或整理这类材料时。
**规范：** 完整读取并执行 [参考材料治理](./modules/reference.md)。

### 正式输入或外部组成部分

**对象：** 需要直接采用、编辑、加工、执行或随成果交付的外部内容。
**边界：** 来源在项目外不等于参考材料；判断依据是它在当前工作中的实际用途。
**处理：** 按它在项目中的实际职责管理，进入项目自有内容、运行内容或交付内容的对应边界。
**触发：** 确定存放位置、导入、修改、执行或随成果交付时。
**规范：** 执行本文件和项目已有规则，不套用参考材料治理。

### 运行数据

**对象：** 程序运行后产生并需要持续保留的数据库、用户数据、上传文件和记录。
**边界：** 可删除的缓存、中间文件和一次性测试数据不属于长期运行数据。
**处理：** 放入明确的运行数据边界，不得成为源码、构建暂存或初始交付包中的隐含依赖。
**触发：** 创建、迁移、备份、恢复、清理或改变运行数据位置时。
**规范：** 执行本文件和项目已有规则。

### 生成物和缓存

**对象：** 可由源码、脚本或工具重新产生的构建结果、依赖目录、缓存和中间文件。
**边界：** 无法重新产生的正式成果、正式数据和人工维护文件不属于生成物。
**处理：** 放入可重建的位置并与人工维护内容区分，不得保存唯一正式成果。
**触发：** 生成、复制、移动、打包、清理或改变生成位置时。
**规范：** 执行本文件和项目已有规则。

### 临时物

**对象：** 删除后不影响项目实质内容的日志、截图、下载物、中间文件、实验文件和 Agent 工作文件。
**边界：** 需要长期保留的审计证据、交接材料、测试基线和正式成果不属于临时物。
**处理：** 放入系统临时目录或项目已确认的临时区，明确生命周期和清理责任。
**触发：** 创建、下载、暂存、移动、引用或清理这类内容时。
**规范：** 完整读取并执行 [临时内容治理](./modules/temp.md)。

### 交付物

**对象：** 会被直接分发、加载、部署、运行或交接的文件和目录。
**边界：** 开发项目根、构建暂存根、交付包根和运行实例根是不同边界，不得互相冒充。
**处理：** 一个目录不得同时承担相互冲突的生命周期；交付物独立验证，运行实例不得反向修改开发项目或构建暂存内容。
**触发：** 构建、组装、复制、压缩、发布、验证或交接交付内容时。
**规范：** 完整读取并执行 [交付物治理](./modules/build.md)。

## 变更和持续维护

- 修改文件前重新读取当前内容，确认没有并行变化；优先精准修改，不得使用旧版本整体覆盖新内容。
- 新内容先确定用途、归属、读者和生命周期，再决定文件名、目录、说明入口和维护方式。
- 项目结构、目录职责或稳定入口发生变化时，同步更新受影响的说明、索引和链接；不得只完成文件移动而留下旧入口。
- 项目扩大后可以拆分说明和专用规则。上级入口只保留当前层级需要的判断、稳定事实和读取路径，不复制下级正文。
- 用户要求形成通用规则的例外时，记录例外对象、范围、生命周期和恢复条件；不得把一次例外改写成所有项目的默认规则。
- 测试、构建和运行产生项目外文件、进程、端口、服务、环境变量或用户配置变化时，记录实际影响，并在任务范围内完成清理或说明保留原因。

## 完成验收

结束涉及文件或目录的工作前，基于实际磁盘重新检查：

1. 工作边界、内容归属和生命周期已经确定，既有项目没有被模板机械改造；
2. 本次产生的正式内容、外部材料、运行数据、生成物、临时物和交付物没有混放；
3. 本次新建或调整的目录确有职责和内容，没有产生空分类、重复说明或无用途层级；
4. 入口、目录索引、说明文件、相对链接和磁盘现状一致，目标能够打开；
5. 生成物可以重建，临时物可以删除，正式流程没有依赖过程文件中的唯一副本；
6. 所有命中的模块已经执行各自的验收；模块涉及固定模板时，重新读取模板源稿和最终产物逐项对照；
7. 项目外变化、运行进程和临时资源已经按任务要求清理，或已明确记录保留范围和原因。
