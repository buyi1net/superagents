# 项目管理

> 全程规则：先理解项目边界、文件归属和现有约定，再读取、创建、修改、移动、重命名或删除文件。任务命中专用模块时，完整读取对应模块后再继续；不得用本文件的摘要代替模块正文。

## 开始工作

按本次任务实际涉及的范围确认以下事实，无关项不为满足检查而创建：

1. 当前工作边界在哪里，当前目录是否为项目根目录；
2. 当前工作属于新项目、既有项目，还是尚未形成长期成果的临时任务；
3. 项目已有的入口文件、目录说明、内容索引、适用规则和稳定约定；
4. 本次会读取或改变哪些文件，哪些入口、索引、链接、构建或交付内容会受影响；
5. 本次读取、新增或取得的内容命中“内容与场景索引”中的哪些条目；
6. 内容是否需要长期维护、重复使用、交接或交付，能否由源码、脚本或工具重新生成。

既有项目优先沿用已经成立的结构、命名和说明来源。不得为了套用本规范而搬动原有内容、重建目录、强制改名或复制已有说明。无法确定工作边界、内容归属或生命周期时，保留现场并向用户说明缺口，不得先写入再补判断。

## 内容与场景索引

> 全程红线：不分阶段，看意思不看词。必须逐条检查下列触发条件；命中后先读取对应规范，再继续操作。

### Agent 入口

**触发与强制措施：** 凡任务涉及 `AGENTS.md`、`CLAUDE.md` 中任意一个文件的创建、迁移、修改、移动、重命名或验收，必须在处理其中任意一个文件前完整读取并执行 [Agent 入口治理](./modules/agent-entry.md)。

### 归档内容 - archive

**触发与强制措施：** 凡任务涉及让旧版本、旧方案或阶段成果退出当前流程但继续保留，或者对已有归档内容进行迁移、压缩、索引、恢复、清理、引用或验收，必须在确定归档位置或开始处理前完整读取并执行 [归档治理](./modules/archive.md)。

### 视觉原型 - design

**触发与强制措施：** 凡任务涉及原型图、交互原型、UI 设计系统、设计令牌、组件规范、设计源文件或原型验证资料的创建、收集、修改、分类、移动、导出、交接或验收，必须在确定材料位置或开始处理前完整读取并执行 [设计材料治理](./modules/design.md)。

### 项目交付 - build

**触发与强制措施：** 凡任务涉及准备直接分发、加载、安装、部署、运行、发布或交接的文件和目录，或者对交付内容进行构建、组装、复制、压缩、校验、验证、清理或验收，必须在判断交付边界、确定组装位置或开始处理前完整读取并执行 [交付物治理](./modules/build.md)。

### 项目文档 - docs

**触发与强制措施：** 凡任务涉及 README、使用说明、技术说明、架构说明、决策、计划、交付说明、运维说明或其它长期项目文档的创建、修改、分类、移动、重命名、索引、交接或验收，必须在确定文档位置或开始处理前完整读取并执行 [项目文档治理](./modules/docs.md)。

### 外部材料 - reference

**触发与强制措施：** 凡要把外部项目、文档、标准、网页、数据、模板、素材、样例、网址或来源记录放入项目，或者整理、维护项目内已有的外部材料，必须在判断内容归属、确定存放位置或开始处理前完整读取并执行 [参考材料治理](./modules/reference.md)。不得因只保留外部链接、尚未取得本地副本或准备把材料作为正式输入而跳过归属判断。

### 执行脚本 - scripts

**触发与强制措施：** 凡任务涉及准备重复执行的构建、测试、部署、迁移、校验、同步、转换、导出或数据处理操作，或者相关脚本的创建、修改、分类、移动、执行、交接或验收，必须在确定脚本位置或开始处理前完整读取并执行 [脚本治理](./modules/scripts.md)。

### 项目源码 - source

**触发与强制措施：** 凡任务涉及业务代码、可维护技术包、独立交付单元或单元测试的读取、创建、修改、移动、重命名、拆分、测试、交付或验收，必须在确定源码位置或开始处理前完整读取并执行 [源码治理](./modules/source.md)。

### 临时文件 - temp

**触发与强制措施：** 凡任务涉及程序运行产生的数据、数据库、用户文件、上传文件、构建结果、依赖目录、缓存、中间文件、日志、截图、下载物、实验文件、一次性脚本、运行副本或 Agent 工作文件的创建、生成、暂存、复制、移动、备份、恢复、引用、清理或验收，必须在判断内容归属、确定存放位置或开始处理前完整读取并执行 [临时内容治理](./modules/temp.md)。

### 项目测试 - tests

**触发与强制措施：** 凡任务涉及跨子项目、跨模块、真实服务、真实接口、端到端流程、回归或交付验收的测试、测试数据和测试产物，必须在确定测试位置或开始创建、修改、分类、移动、运行、交付、清理或验收前完整读取并执行 [测试治理](./modules/tests.md)。

## 写入门禁

> 全程红线：先确定归属，再创建内容。不得为了尽快开始工作，先把文件写入项目根、当前目录或其它方便位置，最后再统一整理。

1. 创建任何文件或目录前，必须完成场景路由，完整读取命中的模块，并确定内容用途、生命周期以及正式位置或临时位置。
2. 正式内容直接写入已经确认的正式位置；归属尚未确定、仍在实验或需要后续筛选的内容，只能进入系统临时目录或项目已经确认的临时区。
3. 工具会自动生成文件或目录时，必须在执行前设置正确的输出位置；不得接受默认输出到当前目录后再计划整理。
4. 完成一次会改变目录结构、目录职责、入口或索引的操作后，必须立即执行本文件对应的入口和索引规则，再继续其它工作。
5. 无法确定内容归属或落点时，不得先行写入；保留现场并解决归属问题。
6. 完成验收只负责复查，不得把本应在写入前完成的归属判断、目录建立和索引维护推迟到任务末尾。

## 项目入口、索引和链接

项目形成需要持续维护的文件后，在项目根建立以下入口：

| 入口        | 职责                                                 |
| ----------- | ---------------------------------------------------- |
| `README.md` | 面向人说明项目用途、使用方法、当前实际内容和阅读入口 |
| `AGENTS.md` | 面向 Agent 说明长期工作边界、适用规则和读取入口      |
| `CLAUDE.md` | 将 Claude Code 路由到同级 `AGENTS.md`                |

已有等效入口时，先确认各自职责，不得机械新增重复说明。Agent 入口的内容和迁移方式以[内容与场景索引](#内容与场景索引)中对应条目指向的规范为准。

- 项目根和实际创建并承载人工维护内容的一级目录使用 `README.md` 作为主要说明入口。README 至少说明所在层级的作用、边界、当前实际直接内容，以及必要的使用方法或进入路径。
- 二级及更深目录不新增项目治理用的 `README.md`。需要说明时，使用最近的一级目录 README、项目文档或已有说明文件；外部项目原本自带的 README 可以随原项目保留，但不得当作本项目新增说明的模板扩散。
- 目录索引只记录当前实际存在、对读者有导航价值的直接内容，不预写尚未创建的目录，也不使用完整文件清单或整棵目录树代替阅读路径。
- 人工维护目录或其直接内容发生新建、删除、移动、重命名、职责变化或入口变化时，同步更新直接包含它的上一级索引。只修改正文且没有改变职责、入口或索引内容时，重新确认索引仍然准确，不机械改写。
- 支持链接的文档中，项目内导航使用可点击的相对链接，外部资源使用完整 URL。链接目标必须实际存在；代码块中的目录树和命令参数不能代替导航链接。

## 目录和内容

- 只在已有实际内容或职责已经确定时创建目录，不预建空目录、空分类或无用途层级。
- 一个目录只承担一个明确的主要职责、项目边界或生命周期。文件按用途和职责归类，不按扩展名机械堆放。
- 同一任务或独立职责的材料集中存放。多个独立主题长期共存且读者需要分别进入时，再建立分类目录；内容规模很小且无需分别导航时，可以保留在上级目录并由上级说明交代。
- 文档按阅读主题归类，脚本按操作用途归类，测试按性质和范围归类，设计材料按设计意图归类。说明文件、工作记录、日志、截图、缓存、构建物和临时物不得互相混放。
- 生成物必须可重建，临时物必须可删除。需要长期保留的 Agent 产物仍按实际用途归入正式内容，不得仅因由 Agent 生成就放进临时区。
- 同一职责只保留一个主要说明来源。入口之间通过链接分工，不复制正文，不把动态状态、实时日志和单次任务进度写成长期规则。

## 变更和持续维护

- 修改文件前重新读取当前内容，确认没有并行变化；优先精准修改，不得使用旧版本整体覆盖新内容。
- 项目结构、目录职责或稳定入口发生变化时，同步更新受影响的说明、索引和链接；不得只完成文件移动而留下旧入口。
- 项目扩大后可以拆分说明和专用规则。上级入口只保留当前层级需要的判断、稳定事实和读取路径，不复制下级正文。
- 用户要求形成通用规则的例外时，记录例外对象、范围、生命周期和恢复条件；不得把一次例外改写成所有项目的默认规则。
- 测试、构建和运行产生项目外文件、进程、端口、服务、环境变量或用户配置变化时，记录实际影响，并在任务范围内完成清理或说明保留原因。

## 完成验收

结束涉及文件或目录的工作前，基于实际磁盘重新检查：

1. 工作边界、内容归属和生命周期已经确定，既有项目没有被模板机械改造；
2. 本次产生的正式内容、外部材料、运行数据、生成物、临时物和交付物没有混放；
3. 本次新建或调整的目录确有职责和内容，没有产生空分类、重复说明或无用途层级；
4. 入口、目录索引、说明文件、相对链接和磁盘现状一致，目标能够打开；
5. 生成物可以重建，临时物可以删除，正式流程没有依赖过程文件中的唯一副本；
6. 所有命中的模块已经执行各自的验收；模块涉及固定模板时，重新读取模板源稿和最终产物逐项对照；
7. 项目外变化、运行进程和临时资源已经按任务要求清理，或已明确记录保留范围和原因。
