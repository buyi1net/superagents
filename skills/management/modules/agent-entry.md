> 本规范只负责统一 `AGENTS.md` 和 `CLAUDE.md` 的创建、迁移、内容归属和验收。是否需要在项目根或子目录建立入口，由用户或其它适用规范决定，不由本规范或执行 Agent 自行判断。

## 核心原则

- 任何 Agent 创建或维护 `AGENTS.md`、`CLAUDE.md` 中的任意一个文件时，都必须确保同级两个文件同时存在并符合本规范。
- `AGENTS.md` 是所有 Agent 的统一入口，也是唯一的入口正稿。
- `CLAUDE.md` 只负责把 Claude Code 路由到同级 `AGENTS.md`，不得形成第二份规则正稿。
- 统一入口不等于把所有规则正文集中写进 `AGENTS.md`；职责独立的详细规则应单独维护，由 `AGENTS.md` 按条件路由。

## 入口解锁顺序

1. 先由用户或其它适用规范确定当前层是否需要入口；本规范不替代这项判断。
2. 重新读取同级现有入口和本次命中的底稿。当前层要求使用标准底稿时，必须使用文件复制操作复制底稿原文件，再做项目化修改；不得用重新生成的相同文本代替实际复制。
3. 按“创建与迁移”处理 `AGENTS.md`，再建立或收敛 `CLAUDE.md`。两份文件不得与当前层其它主体内容并行创建。
4. 重新读取两份最终文件并验证链接。只有同级所需入口全部有效，当前层的 Agent 入口门禁才算完成。

最终内容与底稿相同只能证明文本结果，不能证明执行过底稿复制。缺少复制顺序时，不得声称固定底稿流程通过。

## 创建与迁移

是否建立入口已经由用户或其它规范确定后，按同级文件的实际状态处理：

1. 两个文件都不存在：先创建 `AGENTS.md`，再创建固定的 `CLAUDE.md`。
2. 只有 `AGENTS.md`：保留并核验其内容，再补建固定的 `CLAUDE.md`。
3. 只有 `CLAUDE.md`：创建 `AGENTS.md`，先把 `CLAUDE.md` 的现有内容完整复制过去，确认没有遗漏后，再把 `CLAUDE.md` 改为固定路由。
4. 两个文件都存在：以 `AGENTS.md` 为正稿；`CLAUDE.md` 如果还有路由以外的独有内容，先把这些内容迁入 `AGENTS.md`，再将 `CLAUDE.md` 收敛为固定路由。

完整复制和迁移是为了防止旧规则丢失，不表示原内容已经自动成为正确的长期规则。迁移后必须按本规范重新检查 `AGENTS.md`；发现两份文件内容冲突，或者无法判断旧内容是否仍然有效时，保留现场并向用户确认，不得擅自删除或选择其中一份。

## AGENTS.md

`AGENTS.md` 是当前项目或目录面向所有 Agent 的统一入口，也是唯一的入口正稿。它既要让 Agent 知道从哪里开始工作，也要方便人核对 Agent 将遵守哪些规则。

### 内容从哪里来

按表格从上到下判断，符合一项后不再继续：

| 当前情况 | 处理方式 |
|---|---|
| 用户已经指定内容或结构 | 按用户要求处理 |
| 当前项目或目录已有入口内容 | 保留原有结构，先判断它能否让空上下文 Agent 自主维护；只处理用户要求或已经确认的具体缺口 |
| 新建治理边界且当前场景有专门规范或标准底稿 | 完整执行该规范或底稿 |
| 以上三项都没有 | 使用[通用入口模板](./templates/general-agents.md)创建 |

通用入口模板只用于最后一种情况，不得用它改造已有入口，也不得与其它场景的标准底稿混用。已有入口与标准底稿的章节、名称或写法不同，不等于治理缺口；只有它无法让空上下文 Agent 判断边界、找到场景规则或安全完成当前维护时，才精准补齐缺失能力。除非用户明确要求迁移制度，不得拿标准底稿逐章改造已有入口。无法判断应该执行哪一项，或者现有内容互相冲突时，保留现场并询问用户。

使用通用入口模板时：

1. 在当前层其它主体内容出现前，重新读取[通用入口模板](./templates/general-agents.md)，使用文件复制操作完整复制底稿原文件，再按项目实际内容精准修改；
2. 底稿中的 `##` 章节必须全部保留，名称和顺序以底稿为准；只有明确记录为用户确认的项目专用约束，才可以作为例外；
3. 替换所有尖括号占位内容，删除没有实际内容的示例行，不得留下占位符、虚构目录或尚未成立的链接；
4. 项目专用规则和入口在对应章节补充，不得整体重写底稿或删除开工顺序、通用维护底线和完成检查；
5. 项目化完成后重新读取底稿和最终 `AGENTS.md`，逐项对照 `##` 章节和链接，再解锁当前层。

### 内容边界

**写入：** Agent 开始工作前必须知道的长期规则、工作边界、读取条件和稳定入口，以及用户或其它适用规范明确要求完整保留的内容。

**不写入：** 项目资料和详细说明的正文、工作记录、日志、交接正文、单次任务进度、临时待办和本轮操作过程。这些内容放在各自负责的文件中，需要 Agent 查找时只提供稳定入口。

### 入口与规则正文分层

向 `AGENTS.md` 增加长期内容前，必须先判断它是“开始工作前的入口信息”，还是“进入某个场景后才需要执行的规则正文”。不得因为规则重要，就把完整正文留在入口。

入口只保留以下内容：

- 当前入口的适用范围、项目边界和优先级；
- 能让空上下文 Agent 判断是否命中某个场景的触发条件；
- 命中后必须继续读取的稳定相对链接；
- 在读取专项规则前就必须知道、且省略后会导致错误路由的最小红线。

出现以下任一内容时，原则上应拆为职责独立的规则文件，由入口按条件强制路由：

- 多步操作流程、命令参数或环境检查；
- 失败恢复、清理方法、例外矩阵或故障排查；
- 某个工具、环境、工作流或内容场景专用的详细规则；
- 事故经过、历史原因、长示例或只在命中场景后才需要了解的背景。

拆分时按内容职责选择已有稳定位置：可复用且可执行的工作流进入对应 skill；项目专用的 Agent 运行与协作规则进入项目已经确定的 Agent 配置区；面向人的长期说明进入项目文档区；具体内容场景的治理规则进入该场景的规范文件。不得为了缩短入口，把正文随意移到一个没有职责说明的位置，也不得重复建立作用相同的文件。

已有入口正文需要拆分时，按以下顺序执行：

1. 先确认正文的唯一职责、使用场景、目标位置和直接上级入口；只有形成独立维护边界时才新建目录，不得为每条规则机械建目录或空入口。
2. 先把原正文完整迁入目标文件，再补齐适用范围、专项边界和必要链接；确认迁移没有遗漏后，才能从 `AGENTS.md` 删除原正文。
3. 在 `AGENTS.md` 的既有路由区用“触发条件 + 强制读取路径”替代正文；如果没有路由区，则在不破坏现有结构的前提下建立最小路由。
4. 重新以空上下文 Agent 的视角检查：只读入口时能够判断何时加载专项规则，加载专项规则后能够完整执行，未命中时不会引入无关上下文。

## CLAUDE.md

`CLAUDE.md` 必须使用以下固定内容：

```md
读取同级 [AGENTS.md](./AGENTS.md)。禁止在此文件写入内容。
```

## 验收

创建、迁移或维护入口后，重新读取最终文件并逐项确认：

1. 同级 `AGENTS.md` 和 `CLAUDE.md` 均已存在；
2. `AGENTS.md` 是唯一入口正稿，能让空上下文 Agent 确认当前范围和应读取的规则；
3. `CLAUDE.md` 只含固定内容，且相对链接能够打开同级 `AGENTS.md`；
4. 原 `CLAUDE.md` 中的有效内容没有在迁移时丢失，也没有继续作为第二份规则正文保留；
5. `AGENTS.md` 的内容结构符合用户要求、适用场景规范或已有入口结构；只有从零创建且没有其它依据时才使用通用入口模板；使用通用入口模板时保留了全部 `##` 章节及其顺序，且没有残留占位符或不存在的链接；
6. `AGENTS.md` 没有混入任务进度、临时待办、本轮操作过程或应在其它文件维护的正文；
7. 验收依据来自重新读取的实际文件和链接，不是修改前的记忆或 Agent 自述；
8. 新建入口时能够确认“重新读取依据 → 复制或迁移 → 精准修改 → 最终核验”的顺序发生在当前层其它主体内容之前；
9. 入口只保留判断和路由所需内容；专项流程、命令、异常处理和背景正文已经进入职责明确的文件，且空上下文 Agent 能按触发条件准确找到它。
