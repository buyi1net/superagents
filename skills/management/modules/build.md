> 本规范管理已经确认可直接分发、加载、部署、运行或交接的最终交付物。判断依据是内容生命周期，不是目录是否恰好命名为 `build/`；构建暂存、半成品和待验证包不属于最终交付物。

## 交付边界

- 最终交付区只保存已经确认可交付的目录、发布包、安装包、部署包，以及与其对应的使用说明、更新日志和校验文件。
- 开发项目根、构建暂存根、交付包根和运行实例根分别管理，不得让同一目录同时承担相互冲突的生命周期。
- 开发侧交付说明属于长期项目文档；构建暂存统一放入临时区的 `build/` 分类，不得在最终交付区内暂存或直接开发。
- 单一且规模较小的项目可以使用 `build/<项目>-<版本>/`；只有存在多个交付类型或发布渠道时，才增加有实际内容的分类层级。

## 交付说明

构建前必须在项目 README 或开发侧交付说明中明确交付类型、面向对象、包含范围以及是否包含完整源码、测试和开发脚本。

每种最终交付物必须有对应的使用说明、更新日志和校验信息，并说明：

- 交付类型和适用环境；
- 使用入口、运行方式和验证命令；
- 是否包含完整源码。

交付物内部的说明只描述当前交付内容，不复制开发项目根说明，也不得索引交付包中不存在的开发目录或项目外路径。

## 组装和验证

- 交付目录和 ZIP 同时存在时，二者必须来自同一份逻辑文件清单。
- 待打包目录、半成品和待验证目录留在构建暂存区，不得出现在最终交付区。
- 最终交付目录和压缩包不得在其中直接开发或修改。需要运行验证时，在解压副本或临时副本中执行；验证后复查原交付物没有被运行过程改变。
- `__pycache__`、运行数据库、日志、截图、缓存、锁、进程文件、上传文件和其他运行时生成内容不得进入构建暂存或初始交付包。
- 最终交付物应能根据同一份源码和构建脚本整体删除后重建，不得保存开发侧唯一源文件。
