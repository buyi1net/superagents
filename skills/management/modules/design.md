> 本规范管理原型图、交互原型和 UI 设计系统。判断依据是内容职责，不是目录是否恰好命名为 `design/`；既有项目可以沿用已经稳定使用的设计材料位置。

仅在首次建立设计场景、现有设计治理存在具体缺口，或用户明确要求整理、迁移和审计时使用本规范。已经能够自治的设计区日常维护直接执行项目内规则，不用本规范反复对照。

## 收录边界

设计材料可以包含：

- 页面原型、交互流程和原型图；
- 设计系统、设计令牌和组件规范；
- 只服务于原型的验证资料和原型验证代码。

原型验证代码不得成为正式业务源码。架构、数据模型、技术选型、实施计划、用户手册、研究记录和交付说明属于长期项目文档；正式业务源码属于源码内容；运行截图和临时导出物属于临时内容。

## 解锁顺序

1. 首次使用设计区时，先建立设计区一级 README，写明边界和当前实际内容，再更新直接上级索引。不得把 README 与首份界面规范、原型或设计源文件并行创建。
2. 既有设计区先读取一级 README，确认当前设计意图、正式依据和原型边界，再修改或新增材料。
3. 创建一项设计材料后，立即更新设计区 README；存在两个及以上独立设计意图时，再建立实际需要的分类目录。
4. 任务明确要求“先原型或规范、后正式界面”时，必须先完成并验证对应设计材料，再开始正式界面源码；最终同时存在两者不能证明顺序合规。
5. 截图、浏览器配置、导出文件和原型运行数据在生成前先按临时内容规范确定输出位置，不得落入正式设计材料目录后再清理。

## 组织方式

- 设计资料按设计意图归类，不按文件格式拆散。
- 同一设计意图的相关材料放在同一设计目录。
- 存在两个及以上独立设计意图时，建立有实际内容的二级分类目录，例如 `prototype/`、`ui-system/`。
- 只有一个设计意图且无需分别导航时，可以直接保留在设计区根部，并由一级说明交代实际内容。

设计区默认继承最近的上级 `AGENTS.md`，不得仅因建立设计目录就机械新增局部入口。只有用户、项目既有规则或特定设计工具与导出流程形成独立维护边界时，才按 Agent 入口治理建立局部入口；设计意图、正式依据和材料入口继续由 README 与项目设计说明承担。

## 项目内自治

首次建立或修复设计场景时，项目根入口和设计区 README 必须让空上下文 Agent 找到设计边界、当前设计意图、正式依据和材料入口。项目存在“先设计、后实现”的固定顺序，或者工具、导出和原型验证具有专用门禁时，把触发条件和项目内规则入口写入最近的有效 `AGENTS.md`；不得只把这些要求留在本规范中。

## 验收

1. 设计区 README 早于本次首份设计主体内容，且直接上级索引在继续工作前已经更新；
2. 设计规范、原型、正式源码和临时验证物没有混放或形成反向依赖；
3. 有明确先后要求时，能够根据操作记录确认设计材料完成和验证早于正式界面实现；
4. README 只索引当前实际存在的设计意图和材料，链接能够打开。
5. 没有加载本规范的 Agent 能从项目根找到设计场景，并仅凭项目内入口完成同类维护。
