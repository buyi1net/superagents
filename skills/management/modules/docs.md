> 本规范管理项目长期维护的使用、技术、架构、决策、计划、交付和运维文档。判断依据是内容职责，不是目录是否恰好命名为 `docs/`；既有项目可以沿用已经稳定使用的文档位置。

## 收录边界

长期项目文档可以包含用户说明、技术说明、架构说明、数据格式、实施计划、决策记录、构建说明、交付说明和运维说明。

以下内容不属于长期项目文档：

- 原型图、视觉设计源文件和交互原型；
- 业务源码和正式测试；
- 只用于研究、比较或借鉴的外部参考副本；
- 临时报告、实时日志和过程导出物。

## 语言和命名

- 文档区的 README、目录索引、标题、正文、表格、状态和摘要统一使用简体中文。
- 新建目录和文件名默认使用简体中文；代码标识、命令、路径、URL、产品名和技术缩略词按原文保留。
- 既有英文路径可以保留。没有明确迁移任务并完成链接和交付边界验证时，不为统一语言机械改名。

## 分类和入口

- 文档按读者的阅读目的和文档主题归类，不得用目录名掩盖主题混放。
- 文档区根部原则上只放目录说明文件和实际存在的文档主题目录，例如 `使用说明/`、`技术说明/`、`架构设计/`、`决策记录/`、`交付说明/`。
- 存在两个及以上独立文档主题时，建立二级分类目录；只有一个主题且规模很小时，才可以直接放在根部，并在一级目录说明中写明理由。
- 文档区 README 面向人提供按阅读目的组织的主要入口，不得只重复文件夹名称。需要给 Agent 选择上下文时，由文档区 Agent 入口或其它明确路由文件负责。
