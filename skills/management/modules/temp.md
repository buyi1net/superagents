> 本规范管理删除后不影响项目实质内容、并且可以重新产生的临时内容。判断依据是生命周期，不是目录是否恰好命名为 `temp/`；系统临时目录和项目已确认的临时区都适用。

## 收录边界

临时内容可以包括：

- 构建暂存和待验证包；
- 一次性测试数据和运行副本；
- 实验文件、一次性脚本和下载物；
- 日志、截图、缓存和 Agent 工作文件。

需要长期保留的审计证据、交接材料、测试基线、方案、文档、源码和交付物不属于临时内容，不得仅因当前由 Agent 生成就放入临时区。

## 运行数据和生成物边界

- 程序运行后产生并需要持续保留的数据库、用户数据、上传文件和记录属于运行数据，不属于临时内容。运行数据必须进入明确的运行边界，不得成为源码、构建暂存或初始交付包中的隐含依赖。
- 可由源码、脚本或工具重新产生的构建结果、依赖目录、缓存和中间文件属于生成物。生成物必须可重建并与人工维护内容区分，不得保存唯一正式成果。
- 缓存、中间文件和一次性运行副本只有在删除后不影响项目实质内容且能够重新产生时，才按临时内容管理。
- 无法重新产生的正式成果、正式数据、人工维护文件和需要持续保留的运行数据不得因为位于工具输出目录或由程序产生就按临时内容清理。

## 解锁顺序

1. 先判断使用系统临时目录还是项目临时区。系统临时目录不建立项目入口，但必须在执行前确定准确绝对路径、用途、生命周期和清理目标。
2. 首次使用项目临时区时，先建立临时区一级 README，写明边界、当前实际分类、生命周期和清理责任，再更新直接上级索引。不得先生成缓存、截图、日志、下载物、运行副本或构建暂存，再补 README。
3. 既有项目临时区先读取 README，确认本次内容命中已有分类；没有合适分类时，只在实际输出即将产生时建立新分类并立即更新 README，不预建空目录。
4. 执行工具前设置明确输出路径。工具无法指定输出位置时，先使用系统临时目录中的独立任务目录，不得接受输出到当前工作目录后再移动。
5. 临时分类、文件或目录被清理后，立即更新 README 的当前分类和直接上级索引。已经不存在的分类不得继续写成当前内容，可以在运行说明中写成按需产生的位置。
6. 启动临时进程、服务或浏览器时记录本次创建的准确进程和配置目录，清理时只处理这些目标；不得使用按程序名称结束全部进程的方式清理。

## 组织和生命周期

- 不存在临时内容时，不得为了补说明创建空临时目录。
- 临时区存在后，其一级目录说明应写清边界、当前实际分类、生命周期和清理责任；实时日志不能代替说明。
- 构建暂存统一放在临时区的 `build/` 分类。
- 测试临时数据和运行副本按任务或会话归类，不得把不同生命周期的内容长期混放在临时区根部。
- 临时内容必须可删除并可重新产生，不得成为正式源码、构建流程、测试命令或交付包的唯一依赖。

## 清理

清理前确认待删内容没有被正式流程作为唯一依赖，并确认其中没有需要转为正式文档、源码、测试基线、审计证据或交付物的内容。临时区不得变成未声明的运行数据目录或长期备份区。

## 验收

1. 项目临时区 README 早于本次首个临时主体内容，系统临时目录则在执行前已经确定准确路径和生命周期；
2. 工具实际输出位置与执行前设置一致，没有先污染正式目录或当前目录再整理；
3. 临时内容可删除、可重新产生，不是正式流程的唯一依赖；
4. README 的当前分类与最终磁盘一致，已清理分类没有继续作为当前内容；
5. 文件、目录、进程、服务、端口和浏览器配置均按本次准确目标清理，没有影响用户或其它任务的同名资源。
