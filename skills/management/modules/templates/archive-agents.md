## 给 Agent

1. 本目录只保存已经退出当前流程、但仍需长期保留以便追溯或恢复的内容；归档内容默认只读，不参与当前源码、构建、测试、运行或交付；
2. 先读同级 [README.md](./README.md)，并只打开本次任务涉及的归档记录和归档项；
3. 当前仍在使用、尚未完成、只是临时备份或无法判断生命周期的内容不得归档。

## 开工顺序

1. 同级 `README.md`、`AGENTS.md`、`CLAUDE.md` 必须已经存在并能互相打开；入口不完整时只修复入口，不得先移动、复制、压缩或删除归档内容；
2. 归档前确认内容已经退出当前流程、归档原因、替代关系、目标位置和恢复用途；
3. 实际归档前读取当前本地时间并确定名称，不得使用预计时间、取整时间或事后改写时间；
4. 归档项实际存在后，立即更新 README 和归档记录，再处理下一项；不得预写尚未存在的归档项；
5. 恢复或删除归档项时，先确认当前依赖、唯一来源、恢复目标和影响范围，再执行对应流程。

## 收录边界

可以归档：已废弃的旧版本、旧方案和仍有追溯价值的阶段成果。

不得归档：当前流程仍依赖的内容、唯一正式来源、未完成材料、临时备份、实时日志以及仍需参与构建、测试、运行或交付的内容。

## 组织和记录

1. 归档项可以使用版本化目录、单文件或 `.zip`；需要整体冻结、分发或长期只读保存时使用 `.zip`；
2. 名称使用 `名称-版本-YYYYMMDD-HHmm`，时间取实际执行归档时的本地时间；
3. 每项记录至少包含名称、版本、归档时间、归档原因、被替代内容、替代决策和当前恢复条件；
4. 不为每个归档项机械建立 README，统一由本目录 README 或已有归档索引管理。

## 恢复

1. 恢复前确认归档内容与当前结构、依赖和规则的兼容性；
2. 先恢复到临时副本或明确的新目标，不得直接覆盖当前内容；
3. 恢复后如重新进入当前流程，先按其实际职责完成正式位置的入口、说明和验证，再更新归档记录；
4. 保留原归档还是完成迁移，按项目记录或用户要求处理，不得擅自删除追溯来源。

## 删除

1. 删除归档内容属于破坏性操作，只有用户明确要求或项目已有明确流程时才能执行；
2. 删除前确认它不参与当前流程、不是唯一来源，并记录删除对象、时间、原因和替代定位；
3. 删除实体后把它从 README 的当前归档索引移出；需要保留追溯信息时，放入明确标记为“已删除”的历史记录，不得继续显示为当前可用归档；
4. 用户明确要求连记录一并清除时，按用户指定范围执行。

## 维护结果验收

每次归档、恢复、删除或整理后，结束任务前重新读取实际文件并确认：

1. 归档内容已经退出当前流程，不是当前流程的依赖或唯一来源；
2. 名称和记录中的版本、时间与实际归档时点一致；
3. README、归档记录和磁盘现状一致，没有预写不存在的归档项；
4. 恢复经过兼容性判断且没有直接覆盖当前内容；
5. 删除具有明确依据，保留了任务范围内必要的追溯记录和来源定位；
6. 根据本次操作记录确认入口早于归档主体，归档项实际出现、恢复或删除后立即完成了记录维护。
