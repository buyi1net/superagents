## 给 Agent

1. 本目录只保存已经确认可直接分发、加载、安装、部署、运行或交接的最终交付物及其说明和校验文件；
2. 先读同级 [README.md](./README.md)，再读取项目内对应的开发侧交付说明、构建入口和验证入口；
3. 本目录不是开发项目根、构建暂存区或运行实例，不得在这里边开发边验证。

## 开工顺序

1. 同级 `README.md`、`AGENTS.md`、`CLAUDE.md` 必须已经存在并能互相打开；入口不完整时只修复入口，不得写入或修改最终交付物；
2. 构建前确认交付类型、面向对象、版本、包含范围、源码边界、构建入口和验证方式；
3. 先在项目已确定的构建暂存区组装，生成逻辑文件清单并检查；不得直接在本目录生成半成品或待验证包；
4. 在暂存副本、解压副本或其它明确的临时副本中完成运行和交付验证，清理运行副作用并复核待交付清单；
5. 验证通过后，才把同一份逻辑清单晋级到本目录，并立即更新 README 和校验信息。

## 内容边界

本目录可以保存最终交付目录、压缩包、安装包、部署包，以及与其对应的使用说明、更新日志和校验文件。

开发项目根、唯一源码、构建暂存、待验证半成品、运行数据库、日志、截图、缓存、锁、进程文件、上传文件和其它运行生成物不得进入本目录。

## 组装与验证

1. 最终交付目录和压缩包同时存在时，二者必须来自同一份逻辑文件清单；
2. 使用说明只描述当前交付内容，不得链接交付物之外的本机路径，也不得索引包内不存在的开发目录；
3. 最终交付物必须能从明确的源码和构建入口整体重建，不得保存开发侧唯一文件；
4. 运行验证只在副本中进行，并在验证后确认原交付物未被运行过程改变；
5. 启动外部程序时记录准确进程、端口和临时位置，只清理本次创建的目标。

## 最终物变更

最终交付物形成后不得直接开发或手工补文件。任何运行、修改、重建、替换或补充都会使先前验证失效；发生变化后必须重新执行文件清单、哈希、运行副作用和原件未变检查，再更新 README 和校验信息。

## 维护结果验收

每次构建、晋级、替换或清理交付物后，结束任务前重新读取实际文件并确认：

1. 能根据操作记录确认“暂存组装 → 副本验证 → 最终晋级”的顺序；
2. 最终目录和压缩包来自同一逻辑清单，校验信息可以在目标环境实际使用；
3. 最后一次影响交付内容的操作之后重新完成了全部验证；
4. 最终交付区没有半成品、待验证包、唯一源码或运行生成物；
5. README、使用说明、更新日志、校验文件和磁盘现状一致；
6. 项目外进程、端口和临时资源按准确目标清理，没有影响其它任务或用户环境。
