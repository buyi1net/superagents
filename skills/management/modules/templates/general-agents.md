## 开工顺序

1. 先读本文件和同级 [README.md](./README.md)，确认项目边界、当前实际内容和本次任务入口；不得先修改文件再补读入口。
2. 只读取本次任务需要的说明和内容。目标目录存在更近的 `AGENTS.md` 时，进入或处理该目录前必须先读；没有局部入口时继续执行本文件。
3. 创建、下载、生成、复制、移动或运行内容前，先确定它的用途、生命周期、正式位置或临时位置；凡为本项目进行的调研、实验、测试、构建和验证，都必须优先使用项目根内，或者本项目规则、用户明确指定的项目专用位置。无法判断时保留现场，不得先写入再整理，也不得改用系统临时目录规避判断。
4. 任务引入项目地图中没有的新职责或新内容场景时，先确定长期维护方式、项目内规则和说明入口。现有入口无法让空上下文 Agent 安全指导该场景时，只处理治理缺口，不得直接创建主体内容；新增同类文件或条目不算新的治理场景。

## 项目维护规则

1. `<补充不同任务需要读取的项目专用规则和工作入口，并提供项目内稳定链接。>`
2. `<补充当前项目长期有效的工作边界、唯一正稿、同步要求和用户授权边界。>`
3. 项目入口只保留范围、判断条件、最小红线和稳定读取路径。独立场景的操作步骤、命令、异常处理、例外和历史说明必须在职责归属文件中维护，由本入口按条件路由；不得把所有规则正文堆进入口。
4. 治理先于内容。不得先完成开发、下载、测试、构建或整理，再补入口、说明和索引。
5. 目录和索引只记录当前实际存在且有用途的内容，不预建空分类，不预写尚未出现的目录、文件、链接或完成状态。
6. 新建、删除、移动、重命名直接内容，或者改变目录职责和稳定入口后，立即更新直接上级说明和索引，再继续其它主体工作。
7. 正式内容、外部参考、运行数据、生成物、临时物和最终交付物按实际职责分开。不得把当前目录当作默认落点，事后再搬运整理。
8. 临时物和生成物必须有明确的项目内位置、重建方式、生命周期和清理范围；不得成为正式流程依赖的唯一副本。“只验证一次”“测完删除”“不提交版本控制”、内容因安全要求需要隔离和工具默认行为都不是使用系统临时目录的理由。只有系统或工具确实无法重定向，或者项目不可写且用户明确允许时，才可使用隔离的系统临时位置，并在任务结束前清理；无法清理时必须向用户说明准确路径、保留原因和清理方法。
9. 项目内规则使用相对路径指向本项目的稳定入口。可以补充加载外部 skill，但不得把本机缓存、某台电脑的绝对路径或外部 skill 作为项目能够继续维护的唯一依据。

## 完成检查

结束任务前重新读取实际文件并确认：

1. 本次操作遵守了“先确认边界和入口，再处理主体内容”的顺序；
2. 项目地图、README、局部入口、链接和磁盘现状一致；
3. 新内容已经进入正确职责和生命周期，没有依赖事后整理；
4. 临时文件、运行副作用和项目外资源已经精确清理，或者已记录明确的保留原因和责任；
5. 当前入口足以让没有加载外部管理 skill、不了解本次会话的 Agent 判断项目边界、找到项目内规则并继续维护；
6. 独立场景的规则正文已经进入职责归属文件，入口只保留触发判断、最小红线和稳定路由。
