## 给 Agent

1. 本目录只保存删除后不影响项目实质内容、并且可以重新产生的临时内容；正式成果、唯一数据、长期证据和最终交付物不得放在这里；
2. 先读同级 [README.md](./README.md)，确认当前实际分类、生命周期和清理责任，只读取本次任务涉及的临时内容；
3. 本文件只管理项目临时区。系统临时目录仍按任务确定准确路径和清理范围，不在其中建立项目入口。

## 开工顺序

1. 同级 `README.md`、`AGENTS.md`、`CLAUDE.md` 必须已经存在并能互相打开；入口不完整时只修复入口，不得先生成临时主体内容；
2. 创建、下载或运行工具前，先确认内容确实可以删除和重新产生，并确定准确目标、用途、生命周期和清理责任；
3. 工具输出位置必须在执行前明确设置。工具无法指定时，使用系统临时目录中的独立任务目录，不得接受输出到源码、项目根、当前目录或其它正式位置后再搬运；
4. 新分类或临时内容实际出现后，立即更新 README，再继续下一项主体工作；不得预建空分类或预写不存在的内容。

## 内容边界

可以放入本目录：构建暂存、待验证包、一次性测试数据、运行副本、实验文件、一次性脚本、下载物、日志、截图、缓存和 Agent 工作文件。

不得放入本目录：无法重新产生的源码、文档、设计材料、测试基线、审计证据、项目正式数据、需要持续保留的运行数据和最终交付物。

无法确认删除后果或重建来源时，不得按临时内容处理。

## 创建与使用

1. 不同任务、会话或生命周期的内容使用可准确定位的独立位置，不在临时区根部长期混放；
2. 构建暂存使用 `build/` 分类；其它分类按项目实际用途建立，不因模板示例预建；
3. 启动进程、服务、端口、浏览器或其它外部资源时，记录本次创建的准确标识和配置位置；
4. 临时内容不得成为源码、构建、测试、运行或交付流程依赖的唯一副本。

## 转为正式内容

临时成果需要长期保存时，先确认它已经达到正式内容标准，并确认正式目标的入口、职责和索引已经成立，再直接转入对应正式位置。完成正式位置维护后，清理临时重复副本；不得只在 README 中把临时内容改称正式成果。

## 清理

1. 清理前确认准确目标、创建来源和依赖关系，确保其中没有唯一正式成果、正式数据或需要转存的证据；
2. 只删除本次任务或明确指定的文件、目录、进程、服务、端口和配置，不得按程序名称、模糊路径、宽泛匹配或整个用户环境清理；
3. 清理改变当前分类或内容后，立即更新 README；已经消失的分类不得继续写成当前内容；
4. 无法判断目标是否仍被使用时保留现场，不得为了“保持干净”扩大删除范围。

## 版本控制

项目使用版本控制时，同级 `README.md`、`AGENTS.md` 和 `CLAUDE.md` 属于项目治理文件；临时主体内容按项目实际情况忽略。不得使用一个无法保留治理入口的宽泛忽略规则，也不得把临时主体内容误提交为正式成果。

## 维护结果验收

每次创建、使用、转存或清理临时内容后，结束任务前重新读取实际文件并确认：

1. 所有内容均可删除、可重新产生，不是正式流程的唯一依赖；
2. 工具实际输出位置与执行前确定的位置一致，没有先污染正式目录再整理；
3. README 中的当前分类、生命周期和清理责任与磁盘一致；
4. 需要长期保存的内容已经进入对应正式边界，临时区没有残留唯一副本；
5. 文件、目录、进程、服务、端口和配置均按准确目标处理，没有影响其它任务或用户环境；
6. 根据本次操作记录确认入口早于临时主体内容，内容出现和清理后都立即完成了 README 维护。
